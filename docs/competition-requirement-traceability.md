# 项目如何满足深信服 AI 安全比赛要求

## 1. 结论

本文逐条对应比赛要求、实现证据和能力边界。项目聚焦“大模型应用安全事件的可解释自主调查与处置”这一单一场景。

基础任务和进阶任务已有真实实现。挑战任务具备有界规划、工具调用、观察驱动重规划、多假设反证、任务恢复、内部处置和处置后验证。由于没有真实端点检测与响应（EDR）、防火墙、身份和安全信息与事件管理（SIEM）接口，跨域数据与外部联动部分必须标为仿真或未接入。

赛事方已批准不使用当前不可用的官方平台。本项目使用自研 Web、AutoDL 模型服务和本地 Docker；团队应在提交附件中保留赛事方批准记录。

## 3. 三层任务对应关系

### 基础任务

真实 Prompt 安全链路解决“单一语义分类无法定位优化后缀、单一 Token 变化无法识别直接危险请求”的问题。输出包括语义等级、Token 异常候选、异常起点、固定融合动作和脱敏审计。PCAP 隔离检测作为补充流量证据，不进入冻结 Prompt 指标。

### 进阶任务

离线 RAG 提供 OWASP、MITRE 和协议知识引用；PCAP Docker 工具扩展网络证据能力；版本化剧本、连接器目录和追加式分析员反馈增强专业深度与可运营性。知识和反馈均不能在线改动冻结检测器。

### 挑战任务

统一安全智能体支持自然语言目标、公开计划、最小授权、后台执行、SSE/轮询恢复、多假设反证、观察驱动重规划、跨源时间线、内部处置、独立验证和引用报告。真实与仿真证据在模型、API、页面和报告层都保持区分。

## 4. 创新点

1. 双证据检测：语义危险与 Token 分布变化独立保留，再由固定策略融合，不让生成模型随意改写判定。
2. 可定位的异常证据：除分类外给出 Token 起点或 PCAP 包区间，便于 Wireshark 和人工复核。
3. 证据真实性类型：`real | simulated | derived` 是后端公共契约，不由前端猜测。
4. 多假设反证：攻击假设与正常业务解释同时存在，攻击信号会提高前者并降低后者，普通响应证据可反向调整。
5. 观察驱动重规划：计划不是固定动画，特定工具观察会产生新版本并记录触发理由。
6. 验证后闭环：动作成功不等于处置有效，必须有独立验证观察才能显示已遏制。
7. 隐私最小化任务恢复：SQLite 保存脱敏任务、计划、事件和证据引用，不保存原始 Prompt、payload、Token 文本、私人路径或凭据。
8. 隔离 PCAP 执行：无网络、只读根文件系统、非 root、能力全丢弃、禁止提权和资源限制。

## 5. 明确限制

- 未接入深信服官方平台，原因是平台不可用且赛事方已批准豁免。
- 未接入真实 EDR、防火墙、身份、SIEM 和工单系统；相关跨域演示是仿真。
- 真实 PCAP 没有审计后的逐请求标签时，只能报告检测候选与覆盖范围，不能给出正式总体准确率。
- TLS 加密负载不可见时，不能声称识别了其中的 Prompt 或 payload。
- 检测命中不等于攻击成功，检测未命中不等于全部安全，工具失败不等于发现异常。
- 统一对话工作台当前编排已注册的安全任务；单文件 PCAP 上传仍由 `/lab` 的本地隔离上传入口完成。

## 6. 验收清单

- 身份和知识问答不请求检测授权。
- Prompt 与 PCAP 在读取前展示计划和精确授权范围。
- 切换路由、案件或检查器不会隐式取消任务。
- 页面同时显示支持证据、反对证据和置信度变化。
- 异常、失败、未命中和成功状态有文字标签，不只依赖颜色。
- 报告中的风险结论可追溯到证据 ID。
- 仿真材料在连接器、证据、时间线和报告中保持仿真标签。
- Token 侦探挑战评分和冻结检测阈值未修改。
- 桌面 1440×900 和手机 390×844 无水平溢出和主要控件遮挡。
