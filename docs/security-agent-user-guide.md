# 如何使用 Token Security 安全智能体

## 1. 产品定位

本手册说明如何启动 Token Security、创建安全任务、读取结果并处理常见 PCAP 故障。Token Security 面向“大模型应用安全事件调查与处置”这一单一安全运营场景。

它不是万能聊天机器人。身份、问候和安全知识问题可以直接回答；与安全无关的复杂任务会说明专业范围。系统不会把检测未命中说成全部安全，也不会把检测失败说成发现异常。

## 2. 运行环境

### 2.1 仅查看 Web 界面

```powershell
Set-Location frontend
npm.cmd install
npm.cmd run dev -- --host 127.0.0.1 --port 5173
```

打开 `http://127.0.0.1:5173/super-agent`。仅启动 Web 时，后端数据会显示不可用或降级，这是正常状态。

### 2.2 启动本地 API

```powershell
Set-Location <项目根目录>
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

完整 Prompt 检测还需要 AutoDL 模型隧道和 README 中列出的模型、校准、知识库与评测环境变量。PCAP 检测需要 Docker Desktop、已构建的隔离镜像和本地 PCAP 后端。官方比赛平台不可用，赛事方已批准不接入；提交材料应保留批准记录。

## 3. 页面关系

| 入口 | 作用 | 典型结果 |
| --- | --- | --- |
| `/super-agent` | 从自然语言目标建立可恢复安全案件 | 计划、授权、工具观察、重规划、假设、时间线和报告 |
| `/analyze` | 对单条 Prompt 做真实语义、Token 与知识分析 | 放行、人工复核、拦截或净化后复检，以及异常起点 |
| `/lab` | 独立运行 Prompt/PCAP 攻防实验 | 真实检测结果或明确标注的实验/仿真结果 |
| `/events` | 查看脱敏审计记录 | 请求哈希、检测统计、动作、模型与校准版本 |
| `/evaluation` | 查看冻结评测与消融结果 | Precision、Recall、F1、FPR、定位和延迟 |
| `/challenge` | Token 侦探互动挑战 | 玩家标注、证据复盘和回合得分 |

专业工作区负责“直接使用某项能力”，安全智能体负责“把多项能力组织成一个案件”。Token 侦探挑战是独立互动功能，不参与智能体处置或检测阈值。

## 4. 对话与任务

### 4.1 普通对话

可以输入：

- `你叫什么名字`：返回身份和专业边界，不调用检测工具。
- `你能做什么`：列出可用能力、授权要求和数据边界。
- `什么是提示词注入`：基于批准的安全知识给出原理、常见目的、误报和处置建议。
- `packet 4-4 是什么`：说明这是从第 4 个包到第 4 个包，即单个数据包范围。

一般科普会标为“通用安全知识”，不代表当前环境已经检测到对应攻击。

### 4.2 创建调查任务

1. 在 `/super-agent` 输入调查目标。
2. 点击发送或按 Enter。Shift+Enter 用于换行。
3. 先查看公开执行计划。此时不会自动读取 Prompt 或 PCAP。
4. 需要数据访问时，授权窗口会显示用途、范围、上限和不会保存的内容。
5. 点击“授权并开始”。切换页面或案件不会取消后台任务。
6. 在中央区查看计划进度，在右侧查看证据、假设、工具、时间线和报告。

只有明确输入“取消当前任务”或调用取消按钮才会停止任务。“先不要”“等等”一类模糊表达不会被当作取消。

### 4.3 示例任务

`调查这批 PCAP，找出异常文件并解释攻击目的`

- 计划先检查数据集可解析性，再按每批最多 20 个文件检测。
- PCAP 内容只允许隔离 Docker 路径读取。
- 输出必须区分异常候选、检测失败、当前范围未命中和未覆盖。
- `packet 4-4` 表示证据定位在第 4 个数据包，不是文件名。
- 攻击目的仅作为证据支持的候选，不等于攻击已经成功。

`运行跨域攻防演示并生成处置报告`

- 使用版本化内置仿真端点、身份和日志证据。
- 仿真证据不会进入真实评测指标。
- 工具观察可触发计划修订和攻击框架映射。
- 内部处置完成后必须独立验证；验证不可用时不能显示“已闭环”。

## 5. 如何阅读运行结果

### 5.1 状态含义

| 状态 | 含义 | 正确处理 |
| --- | --- | --- |
| 发现异常候选 | 规则或行为检测命中可疑模式 | 查看证据、反证、目的候选和响应侧信息 |
| 当前范围未命中 | 已完成的检测范围内没有命中 | 不得表述为“文件全部安全” |
| 检测失败 | 工具没有得到可验证结果 | 查看错误码，修复 Docker、格式、超时或服务问题后重试 |
| 已完成 | 计划执行完并生成结论 | 仍需阅读限制与未覆盖范围 |
| 已遏制 | 内部动作成功且独立验证有效 | 只代表平台内部动作，不代表真实外部设备已联动 |
| 降级 | 部分工具不可用但已有结果被保留 | 根据失败步骤补测，不要忽略已有证据 |

### 5.2 证据真实性

- `真实检测`：真实工具对已授权输入产生的直接结果。
- `仿真`：版本化内置演示数据，用于展示端点、身份、日志和处置协同。
- `派生`：根据已引用证据生成的解释、映射、方案比较或报告。

派生证据不能替代直接检测证据，仿真证据不能被写成真实环境告警。

### 5.3 完整可审计决策链

页面公开任务理解、候选假设、支持证据、反对证据、工具选择、观察、置信度变化、计划修订、处置验证、结论和限制。这些信息足以让评委复核智能体为什么采取某一步。

系统提示词、模型内部临时草稿、原始推理 Token 和私人数据不是安全调查证据，因此不展示。这样既满足可解释和可审计要求，也避免把不可靠草稿或敏感信息当作正式依据。

## 6. PCAP 使用与故障处理

上传单个 `.pcap` 或 `.pcapng` 的真实入口在 `/lab`。批量数据集分诊使用 `/super-agent` 或旧 PCAP 工作区的授权数据源。文件扩展名正确不代表格式一定有效。

常见失败及处理：

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 解析失败 | 文件损坏、截断、格式不受支持 | 用 Wireshark 打开并检查文件类型与包数量 |
| Docker 不可用 | Docker Desktop 未启动或镜像缺失 | 启动 Docker，执行隔离门禁验证 |
| 超时 | 文件过大、流量复杂或资源限制触发 | 缩小授权批次，保留失败记录后重试 |
| 没有 HTTP 证据 | TLS 加密或样本不是 HTTP | 转向 TLS、DNS、TCP 和流量行为证据 |
| 检测完成但未命中 | 当前规则没有命中 | 查看协议覆盖、反证和未覆盖范围，不下“全部安全”结论 |

## 7. 智能体资源

- 检测技能：四套版本化剧本，只允许引用 17 个注册工具。
- 安全知识库：OWASP LLM Top 10、MITRE ATLAS、ATT&CK 和本地 PCAP/协议知识。
- 数据连接器：显示真实可用、内置仿真、降级或未接入状态，不允许输入任意连接器 URL。
- 调查报告：Markdown 报告只引用公开证据，包含发现、支持、攻击目的候选、不能证明的内容、失败、未覆盖范围、建议和处置状态。
- 分析员反馈：误报、漏报、确认或不确定只形成追加式审计记录，不在线修改冻结阈值。

## 8. 比赛演示建议

推荐用一句话开始：`调查这批大模型应用流量，找出异常文件，分析攻击目的并生成处置报告。`

演示顺序：目标理解 → 公开计划 → 范围授权 → 真实 PCAP 或 Prompt 检测 → 证据与反证 → 计划修订 → 明确标注的跨域仿真 → 内部处置 → 独立验证 → 引用报告。

录屏时同时展示连接器状态和真实性标签。不要声称已连接真实 EDR、防火墙、SIEM 或身份平台，也不要展示私人 Prompt、payload、文件路径、IP、端口、账号或凭据。
