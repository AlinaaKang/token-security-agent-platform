# 基础任务三分钟演示脚本

## 0:00-0:20 痛点

打开“安全分析”页。

讲解：平台解决一个入口防护痛点，即整句分类不能定位优化型后缀，纯 Token 变化点又可能放过没有突变的直接危险请求。基础任务把语义危险判断和 Token 异常定位组成一条可审计证据链。

## 0:20-0:50 架构

指向工作模式、冻结样本和 Token 风险轨道。

讲解：Qwen3Guard 先给出规范化语义等级；一次 Qwen2.5 前向得到每个用户 Token 的 entropy 与 NLL，Entropy-CPD 在线累积变化；固定融合表根据两路证据和 analysis/gateway 模式选择放行、拦截或人工复核，并写入脱敏事件。

## 0:50-1:20 无害输入

输入一条普通安全问题并点击“开始检测”。

展示：

- 未发现 Token 异常
- 语义安全
- 放行
- 已写入脱敏审计

切到“安全事件”，展示内容哈希、分数、动作和校准版本，强调没有 Prompt 列。

## 1:20-2:00 冻结真实 ID

回到“安全分析”，从冻结样本中依次选择一个 GCG、AutoDAN 或 AdvPrompter ID，点击“检测样本”。

展示：

- 浏览器只看到 sample ID 和攻击族
- Token 轨道只显示 T0/T1 等序号
- Token 异常候选
- 异常起点
- 语义危险类别
- 两路证据融合后拦截

不要在屏幕、讲稿或日志中展示攻击原文。

## 2:00-2:40 冻结评测

打开“评测中心”。

讲解：

- 测试集 663 条，三方法使用相同冻结划分。
- Window NLL 的整句分类 F1 最高，不能隐藏这一结果。
- Entropy-CPD 的独特输出是 Token 起点定位。
- 低误报阈值在开发集选择，冻结 test 的实际 FPR 原样公开。

展示 GCG、AutoDAN、AdvPrompter 召回率，以及 BEAST、AutoDAN-HGA“未评测”。

## 2:40-2:55 知识证据

回到“安全分析”，切换到“证据与报告”。展示官方来源链接、Top-3 知识卡和“模型生成报告”或“模板降级报告”，强调页面明确写着“知识证据不改变基础判定”。不要展示受保护 Prompt、suffix 或 Token 文本。

## 2:55-3:00 局限与进阶

讲解：Qwen3Guard 是 Apache-2.0 第三方工程层，当前 6/6 与 9/9 只是功能验收，不是独立语义准确率。知识库是离线证据层，不会改变基础动作；在线更新与反馈闭环仍是下一阶段。

结束前确认页面右上角显示“部署校准一致”，评测中心明确显示“尚未进行独立冻结语义评测”。
