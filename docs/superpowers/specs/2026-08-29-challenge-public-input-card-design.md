# 挑战关卡公开输入任务卡设计

## 目标

在 Token 侦探挑战的每一关开始时展示与本关对应的输入背景，让玩家知道三位侦探正在分析什么，同时保持受保护攻击 Prompt、优化 suffix 和 Token 文本不进入浏览器、审计记录或持久化结果。

## 用户体验

任务卡位于挑战进度条之后、侦探小队之前，使用全宽“案件材料带”，不嵌套装饰卡。标题固定为“本关待检输入”。

公开策略分为两类：

- `full`：用于 `普通无害` 与 `无害格式突变`。显示完整、预先审核的安全 Prompt，并标记“公开安全样本”。
- `redacted`：用于直接危险、GCG、AutoDAN 与 AdvPrompter 等受保护样本。只显示预先编写的任务意图、公开描述和固定遮罩“[对抗攻击内容已隐藏]”，并标记“受保护样本”。

任务卡在进入每关后立即可见，调查回放、提交答案、重试本关和进入下一关时始终跟随当前关卡。它不参与评分，不改变语义、CPD、融合结果或处置动作。

若公开任务卡缺失或字段无效，页面显示“公开材料暂不可用”，但检测、调查、评分和下一关流程继续工作。

## 数据契约

`LabScenario` 增加一个确定性的公开输入对象：

```text
public_input:
  disclosure: full | redacted
  content: 非空公开文本
  intent_summary: 非空中文意图摘要
  redaction_notice: null | "[对抗攻击内容已隐藏]"
```

字段不得命名为 `prompt`、`suffix`、`token_text`、`token_id`、`query_text`、`raw_output`、`guard_raw_output` 或 `hidden_reasoning`，以保持现有 `FORBIDDEN_PUBLIC_KEYS` 契约不变。

合成安全场景的 `content` 直接来自后端现有 `_SYNTHETIC_SCENARIOS` 中已经执行的安全文本，保证展示内容与实际检测输入完全一致。

受保护场景的 `content` 和 `intent_summary` 只能来自按攻击家族维护的静态公开描述，不得从 Demo 数据集原文截断、替换、总结或动态清洗。后端不读取真实样本正文来生成任务卡。

`LabRunResult` 保持不变，不增加公开输入或原文副本。任务卡只属于场景目录响应，避免检测运行、审计存储和工具执行结果持久化该文本。

## 场景映射

安全场景：

- `synthetic_safe`：完整展示 `Explain why input validation is useful in a web application.`，意图为“解释 Web 应用输入校验的价值”。
- `synthetic_shift`：完整展示现有多行 Checklist 输入，意图为“总结输入校验并处理明显格式变化”。

受保护攻击家族：

- `direct_unsafe`：公开描述“直接请求危险或违规内容，具体目标已隐藏。”
- `gcg`：公开描述“正常请求结构后附加了优化生成的对抗字符串。”
- `autodan`：公开描述“自然语言角色与指令包装试图改变模型安全边界。”
- `advprompter`：公开描述“自动化提示生成器构造了对抗性请求。”

所有受保护场景均使用固定遮罩“[对抗攻击内容已隐藏]”。场景目录中出现未知受保护家族时，不推断正文，返回通用描述“受保护对抗样本，具体内容已隐藏。”。

## 前端结构

新增独立 `ChallengeInputCard` 组件，只接收当前 `ResolvedChallengeRound` 的公开输入对象。组件不请求 API、不读取 `LabRunResult`，也不保存本地状态。

`resolveChallenge` 将场景目录里的公开输入对象复制到对应关卡；复制是字段级白名单，不使用对象展开。挑战页根据 `session.roundIndex` 选择当前关卡并渲染任务卡。

任务卡结构：

```text
本关待检输入                      公开安全样本 / 受保护样本
任务意图  ……
输入材料  ……
          [对抗攻击内容已隐藏]    仅受保护样本显示
```

完整安全输入使用可换行的等宽文本区域；受保护描述使用普通正文和独立遮罩行。桌面保持紧凑横向信息带，`760px` 以下改为纵向排列。所有长文本设置 `min-width: 0` 与 `overflow-wrap: anywhere`，不得产生横向滚动。

## 隐私与安全边界

- 不修改或放宽 `FORBIDDEN_PUBLIC_KEYS`。
- 不向 `LabScenario` 或前端类型增加名为 `prompt`、`suffix` 或 Token 文本/ID 的字段。
- 受保护任务卡不得依赖真实数据集正文、模型输出、日志、检索词或检测信号。
- 不将公开任务卡写入 `LabRunResult`、SQLite、审计事件、SuperAgent 任务或报告。
- 前端序列化测试必须确认受保护关卡不包含已知私密哨兵值、原始 suffix 和受禁止字段名。
- 任务卡是教学上下文，不声称还原真实攻击正文，也不用于证明攻击覆盖率。

## 错误处理

后端场景目录构造失败时沿用现有 API 错误处理。单个场景缺少合法公开输入对象时，前端定义解析层将其标记为不可用，不构造部分文本或猜测攻击家族内容。

任务卡不可用不阻塞挑战；关卡仍可执行并根据真实脱敏结果评分。

## 测试与验收

后端测试：

- 合成安全场景返回 `full`，且 `content` 与实际检测输入相同。
- 每个受保护家族返回 `redacted`、固定遮罩和对应静态公开描述。
- 场景目录和运行结果继续通过 `assert_public_payload`。
- 受保护目录响应不包含真实样本哨兵值或任何禁止字段名。

前端测试：

- `resolveChallenge` 将正确任务卡绑定到每个关卡，未知或缺失对象变为不可用。
- 进入挑战立即显示本关任务卡；下一关、重试和退出后不串用上一个关卡内容。
- 安全关显示完整多行文本；攻击关只显示公开描述和固定遮罩。
- 受保护页面文本不包含原始 Prompt、suffix、Token 文本/ID 或私密路径。

浏览器验收：

- 桌面与 `390x844` 手机均显示当前关卡材料，无重叠或横向溢出。
- 完成一关进入下一关后任务卡同步切换。
- 任务卡出现不会增加 Lab Run 或分析请求数量。
- `/analyze`、`/lab` 与 `/super-agent` 行为保持不变，控制台错误为零。

## 非目标

- 不展示或动态清洗真实 GCG、AutoDAN、AdvPrompter suffix。
- 不允许用户在挑战页编辑或提交任务卡文本。
- 不新增一套 Prompt 数据库、管理后台或内容审核工作流。
- 不改变挑战评分、调查回放、检测算法、AutoDL 模型或工具执行逻辑。
