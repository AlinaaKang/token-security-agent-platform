# 证据约束对话与推荐追问设计

## 目标

将现有基于关键词和固定回复的安全对话升级为自然、连续且可审计的多轮交流。用户既可以自由输入，也可以点击系统根据当前案件状态给出的推荐问题。Prompt 与 PCAP 检测结果继续由现有检测工具产生，大语言模型只负责理解追问和解释公开证据，不得改写检测结论或虚构工具结果。

## 方案选择

采用“推荐追问 + 自由输入 + 本地大模型解释”的混合方案。

- 不采用纯固定问答，因为它无法理解用户表达变化，也不足以体现智能体的上下文能力。
- 不采用完全开放、无证据约束的大模型聊天，因为它可能虚构安全结论、工具调用或处置结果。
- 复用 AutoDL 已加载的 Qwen2.5，不增加第三方在线 API、额外模型下载或新的敏感数据出口。

## 职责边界

### 检测与事实层

Qwen3Guard、Entropy-CPD、PCAP 解析器和已有安全工具是案件事实来源。它们产生风险等级、异常位置、攻击类别、Packet 范围、置信度、工具状态、证据引用和限制条件。最终处置策略仍由现有固定策略与授权规则控制。

### 对话解释层

Qwen2.5 接收经过脱敏和结构化的当前案件摘要、公开证据、限制条件、最近对话上下文以及用户问题，生成自然语言回答。对话层不得接收原始敏感 Prompt、完整 PCAP 内容、隐藏推理或工具私有输出。

### 知识增强层

当问题涉及攻击原理、术语或处置建议时，复用现有安全知识库检索最多三条相关知识证据。知识内容用于解释和引用，不覆盖本次案件检测事实。

## 推荐追问

每次智能体回答、检测完成或工具状态变化后，在最新智能体消息下方显示最多四个推荐问题。按钮使用简短的自然语言，不显示为操作命令。

### 初始对话

- 你能帮助我做什么？
- 什么是提示词注入？
- 怎样开始一次 Prompt 调查？
- 怎样上传并调查 PCAP？

### Prompt 发现风险

- 具体发现了什么问题？
- 为什么判断为高风险？
- 异常从哪个 Token 开始？
- 应该怎样修改这段 Prompt？

### Prompt 安全或证据不足

- 为什么可以放行？
- 这个结论有什么局限？
- 是否还有未覆盖的风险？
- 怎样进行更严格的复检？

### PCAP 发现异常

- 哪些 Packet 最可疑？
- 可能是什么攻击类型？
- 攻击目的是什么？
- 下一步应该怎样处置？

### 工具失败或降级

- 为什么没有得到结果？
- 哪个工具执行失败了？
- 还缺少什么证据？
- 怎样重新检测？

点击推荐问题等同于用户发送该问题：问题先作为右侧用户消息进入当前会话，回答随后作为左侧 Token Security 消息出现。一次只能发送一个问题；任务运行或回答生成期间禁用重复点击。

## 对话数据流

1. 用户自由输入或点击推荐问题。
2. 意图路由判断是普通交流、案件追问、开始检测、控制任务还是越权请求。
3. 案件追问读取当前任务的公开结构化事实和最近对话；无当前案件时不得声称已经检测。
4. 需要专业知识时执行本地检索，并把知识引用与案件证据分别标注。
5. Qwen2.5 按严格输出约束生成回答；输出包含直接结论、证据依据、限制和可选下一步。
6. 回答完成后，根据最新任务状态重新计算推荐追问。

## 回答约束

- 案件事实必须来自当前任务公开证据，并保留证据引用。
- 没有证据时明确回答“当前证据不足”，不能把未命中解释为完全安全。
- 工具失败时解释失败工具、公开错误类型和可重试建议，不能生成安全结论。
- 普通问候、自我介绍和能力询问可以直接回答，不启动检测或申请权限。
- 复杂的非安全请求说明专业边界，并引导回大模型应用安全场景。
- 模型生成超时、格式错误或资源不足时，降级为确定性证据摘要和固定推荐追问；已有对话与检测结果不得丢失。

## 会话与隐私

- 服务端继续只保存脱敏占位消息和公开证据，不持久化原始 Prompt。
- 浏览器本地历史继续保存用户原始输入，并按任务删除机制清理。
- 浏览器在追问请求中临时携带当前任务最近四轮本地消息；后端完成本轮生成后立即丢弃，不写入数据库、日志或报告。
- 提供给 Qwen2.5 的上下文仅限当前任务，服务端验证数量和长度，避免跨案件串联信息或无限扩张。
- PCAP 只提供文件标识、检测统计、异常 Packet 范围和脱敏证据摘要，不传递原始载荷。

## 界面呈现

- 推荐问题位于最新一条智能体回复下方，与消息气泡视觉关联。
- 使用浅蓝描边的紧凑按钮，桌面端可换行排列，移动端纵向排列，文字完整可读。
- 点击后立即形成右侧用户消息，随后显示生成状态，完成后出现左侧回答。
- 输入框始终保留；推荐问题是辅助入口，不限制自由表达。
- 推荐问题不会遮挡发送按钮、本页引导或右侧案件检查器。

## 验收标准

- 用户可以用不同措辞追问 Prompt 或 PCAP 结论，不依赖固定关键词。
- “为什么有问题”“是什么问题”“证据在哪里”等问题能引用当前案件事实回答。
- 最新智能体回复后显示与案件状态匹配的最多四个推荐问题。
- 点击推荐问题后保持“用户在前、Token Security 在后”的消息顺序。
- 无证据、工具失败和检测未命中得到不同且准确的回答。
- 模型不可用时仍返回确定性摘要，现有检测与会话不受影响。
- 原始 Prompt、PCAP 载荷和隐藏推理不会进入服务端持久化、日志或公开回答。
- Prompt 与 PCAP 对话均可刷新恢复并继续追问。

## 测试策略

- 单元测试覆盖案件状态到推荐问题的映射、最大数量和去重。
- 单元测试覆盖对话上下文脱敏、证据约束和无证据降级。
- 协调器测试覆盖自由措辞追问、模型失败降级和消息顺序。
- API 集成测试覆盖同一任务多轮消息、证据引用与隐私字段排除。
- 前端测试覆盖推荐问题显示、点击发送、忙碌状态、自由输入保留和移动端布局。
- 在 AutoDL 上执行 Prompt 风险、安全、工具失败与 PCAP 异常四类冒烟验证。
