# 进阶任务完成设计：离线知识增强与平台内真实工具

## 1. 背景与目标

项目题目保持为“面向 AI 安全的 Token 流量异常检测智能体平台”。基础任务已经完成语义 Guard、Entropy-CPD、固定融合和处置决策。进阶任务解决的痛点是：

> 在不泄露原始 Prompt、攻击后缀和 Token 文本，也不改变基础检测动作的前提下，为研判补充可追溯的官方知识依据，并将处置结果转化为可验证的平台内部动作。

进阶任务包含两个增量：

1. 将现有 `official-v1` 离线知识快照扩充为 `official-v2`，完成开发集与冻结测试集评测。
2. 将现有三个 `dry-run` 工具扩展为用户显式确认后执行的平台内部真实工具，同时保留预览用于对照。

自动规划、自动调用工具、观察反馈和重新规划不属于本阶段，保留给最终任务 SuperAgent。

## 2. 设计原则

- **基础动作不变**：知识检索、报告生成和工具执行不能降低或改写基础检测给出的 `decision`。
- **隐私最小化**：知识智能体、数据库、日志、报告和证据包均不接收或保存原始 Prompt、攻击 suffix、Token 文本或模型原始输出。
- **真实但不夸大**：工具真实写入本平台状态并生成可核验回执，但不声称已经联动外部防火墙、EDR 或工单系统。
- **默认人工确认**：进阶任务中的真实工具必须由用户逐项确认执行；自动执行属于最终任务范围。
- **失败可降级**：知识或报告失败不阻断基础检测；工具失败不能导致更宽松的动作。
- **开发集与测试集隔离**：只在开发集选择参数，冻结测试集只运行一次，不依据测试结果继续调优。

## 3. 总体架构

```text
输入
  -> Qwen3Guard 语义检测
  -> Entropy-CPD Token 分布突变检测
  -> 固定融合与基础动作
  -> SafeQueryBuilder 脱敏结构化查询
  -> official-v2 本地 SQLite FTS5 Top-3
  -> 严格引用报告或确定性模板回退
  -> 用户查看工具预览
  -> 用户显式确认
  -> 平台内真实工具执行
  -> SQLite 审计留痕与脱敏证据包
```

知识增强和工具层都位于基础判定之后。任何下游模块均不能修改 `detector_score`、`suspicious_span`、语义证据、融合原因或原始处置动作。

## 4. `official-v2` 离线知识快照

### 4.1 内容

`official-v2` 保留 `official-v1` 的 12 张 OWASP、MITRE ATLAS 和 NIST 卡片，并新增 6 张官方知识卡：

- OWASP：供应链风险
- OWASP：数据与模型投毒
- OWASP：无界资源消耗
- NIST：AI 600-1 Generative AI Profile
- 中国国家互联网信息办公室：《生成式人工智能服务管理暂行办法》
- 中国国家互联网信息办公室：《人工智能生成合成内容标识办法》

快照共 18 张卡。每张卡继续包含固定 `knowledge_id`、发布方、风险域、摘要、指标、建议、检索标签、官方 URL、版本和内容哈希。

发布方枚举和 URL 白名单增加中国国家互联网信息办公室官方域名。加载器继续拒绝未知字段、重复 ID、非法 URL、非白名单来源和哈希不一致。

### 4.2 检索

继续使用内存 SQLite FTS5，不引入向量数据库或在线检索。固定检索方式为：

- 路由标签权重：2.0
- 词法权重：1.0
- 返回数量：Top-3
- 同分规则：按 `knowledge_id` 升序

选择该方案是因为当前知识规模小、来源结构化，FTS5 的确定性、低延迟和可复现实验性比引入额外向量服务更适合比赛交付。

### 4.3 安全查询边界

SafeQueryBuilder 只使用脱敏检测元数据。存在有效 CPD 起点时，原始输入仅在内存中用于起点前缀截断，随后完成长度限制与秘密信息脱敏；生成的查询不进入 API、SQLite、日志、报告或调试输出。

知识智能体只接收：

- 语义等级与类别
- CPD 是否告警及异常起点索引
- 固定融合原因与处置动作
- 工作模式
- 冻结样本的攻击族名称

## 5. 检索评测设计

评测文件升级为 `knowledge-evaluation-v2`，共 72 条不含 Prompt 和攻击指令的脱敏元数据案例，覆盖 9 个风险域：

- prompt injection
- jailbreak
- sensitive information disclosure
- excessive agency
- supply chain
- data and model poisoning
- unbounded resource consumption
- governance
- incident response

数据拆分：

- 36 条开发案例：用于修正卡片标签和检索参数。
- 36 条冻结测试案例：冻结后只运行一次，不用于继续调参。

指标与验收目标：

- Hit@3 不低于 95%
- 引用有效率为 100%
- 知识开关前后动作一致率为 100%
- 同时报告 Hit@1、MRR 和各风险域结果

上述数值是待执行实验的验收目标，不是当前 `official-v1` 已取得的结果。当前基线仍为 36 条 fixture 上 Hit@3 97.22%、引用有效率 100%、动作一致率 100%。

## 6. 有依据报告实验

### 6.1 模型与输入

继续复用 AutoDL 上的 Qwen2.5-7B，不增加第三个模型。报告模型只接收脱敏结构化事实和本次 Top-3 的精简知识字段。

输出仍为严格单个 JSON 对象，只允许：

- `summary`
- `evidence_ids`
- `handling_steps`
- `limitations`

引用必须来自本次真实返回的 `knowledge_id`。未知字段、代码围栏、前后缀文本、JSON 解析失败、重复或未知引用、超时均触发确定性模板回退。固定记录失败类别，但不记录模型原始输出。

### 6.2 开发与冻结测试

开发集使用 15 条受保护样本，GCG、AutoDAN、AdvPrompter 各 5 条。比较 9 组配置：

- 最大新 Token：64、96、128
- 超时：3 秒、5 秒、6 秒

只依据开发集选择配置。冻结测试使用另外 30 条受保护样本，三个攻击族各 10 条。

冻结测试验收目标：

- 模型报告成功率不低于 90%
- 引用有效率为 100%
- 动作一致率为 100%
- 报告生成 P95 不高于 5 秒

所有失败继续返回确定性模板，因此模型报告成功率未达标时系统仍可用，但实验结论必须如实标为未达标。

## 7. 三个平台内真实工具

### 7.1 网关处置执行器

工具从服务器端已冻结的运行结果读取动作，前端不能提交或覆盖新动作：

| 基础动作 | 平台内部执行结果 |
| --- | --- |
| `ALLOW` | 创建放行授权回执 |
| `REVIEW` | 将事件置入本地人工复核队列 |
| `SANITIZE_RECHECK` | 将事件置入本地净化复检队列 |
| `BLOCK` | 创建本地拦截回执 |

该工具不调用外部防火墙或目标模型。页面和报告统一标注“平台内部执行”。

### 7.2 脱敏安全事件工具

用户确认后创建持久化事件，保存：

- 事件编号、创建时间和来源运行编号
- 风险分数与等级
- 语义等级与类别
- CPD 状态与异常起点索引
- 融合原因、基础动作和当前处置状态
- 本次引用的 `knowledge_id`
- 模型、规则、校准和知识快照版本
- 工具执行状态与回执编号

不保存原始 Prompt、suffix、Token 文本、检索词、报告正文或模型原始输出。

### 7.3 脱敏证据包工具

工具生成可下载的规范化 JSON 文件，包含：

- 检测版本与来源信息
- 脱敏检测结论
- CPD 状态和起点索引
- 有效知识引用
- 已执行工具回执
- 证据包生成时间

文件采用稳定字段顺序与 UTF-8 编码，并计算 SHA-256。下载接口返回生成时的同一字节序列，使评委能够重新计算哈希验证完整性。

## 8. API 设计

保留现有预览接口：

```text
POST /api/v1/lab/runs/{run_id}/tools/{tool_id}/dry-run
```

新增：

```text
POST /api/v1/lab/runs/{run_id}/tools/{tool_id}/execute
GET  /api/v1/lab/runs/{run_id}/executions
GET  /api/v1/lab/artifacts/{artifact_id}/download
```

执行请求包含：

```json
{
  "confirmed": true,
  "idempotency_key": "客户端生成的 UUID"
}
```

设计约束：

- `confirmed` 不为 `true` 时拒绝执行。
- 同一运行、工具和幂等键只产生一次执行结果。
- 工具动作完全从服务端运行快照派生。
- 运行不存在或已过期时返回明确的 404 或 410。
- 证据包不存在、生成失败或哈希不一致时禁止下载。
- API 返回脱敏结构，不返回任何禁用字段。

## 9. 数据持久化

沿用项目现有 SQLite 审计边界，新增三类记录：

### `lab_tool_executions`

- `execution_id`
- `run_id`
- `tool_id`
- `idempotency_key`
- `status`
- `effective_action`
- `receipt_id`
- `error_code`
- `latency_ms`
- `created_at`

对 `(run_id, tool_id, idempotency_key)` 建唯一约束。

### `lab_security_cases`

保存第 7.2 节列出的脱敏事件字段，并以 `case_id` 作为稳定引用。结构化数组使用规范化 JSON 保存。

### `lab_artifacts`

- `artifact_id`
- `run_id`
- `execution_id`
- `media_type`
- `payload`
- `sha256`
- `created_at`

`payload` 只允许经过公开载荷校验器的脱敏 JSON 字节。这样可以保证下载内容与哈希对应，并避免临时文件生命周期问题。

## 10. 事务、失败与安全规则

- 每次真实工具执行使用单个数据库事务；回执和对应状态要么同时成功，要么一起回滚。
- 工具失败只记录固定错误码，不记录异常中的潜在敏感文本。
- 失败后保留基础动作；不得自动降级为更宽松动作。
- 重试必须复用原幂等键，避免重复事件和重复证据包。
- 每个公开响应、持久化事件和证据包都通过禁用字段递归检查。
- 报告模型超时或不可用时，知识证据与工具仍可独立工作。
- 数据库不可写时，真实工具明确失败，页面不得显示成功回执。

## 11. Web 交互

在 `/lab` 结果区增加“工具执行中心”，不改变稳定的 `/analyze` 基础页面。

每个工具提供两种操作：

- **预览**：调用现有 `dry-run`，展示预计动作，不持久化真实结果。
- **确认执行**：弹出简短确认框，说明这是平台内部动作；确认后调用真实执行接口。

执行后展示：

- 成功、失败或处理中状态
- 平台内部动作
- 耗时
- 执行编号与回执编号
- 证据包 SHA-256 和下载按钮

刷新页面后通过执行列表接口恢复状态。按钮在请求期间禁用，重复点击依靠前端禁用和服务端幂等双重保护。界面不展示原始 Prompt、攻击 suffix、Token 文本或模型思维过程。

## 12. 测试与验收

### 后端

- `official-v2` 卡片 schema、白名单、重复 ID 与哈希校验
- FTS5 确定性排序和 72 条评测脚本
- 报告 JSON、引用校验、超时和模板回退
- 三个真实工具的成功、失败、幂等和事务回滚
- 禁止前端覆盖动作
- 公开载荷、SQLite 和证据包隐私扫描
- 下载字节与 SHA-256 一致性

### 前端

- 预览与真实执行状态明确区分
- 未确认不能执行
- 请求中禁止重复操作
- 刷新后恢复回执
- 证据下载状态与错误提示
- 桌面、移动端和 reduced-motion 回归
- `/analyze` 基础页面回归测试

### AutoDL 实验

- 监控 9 组开发集配置，记录超时与失败类型
- 固定最佳开发配置后执行一次冻结测试
- 输出总体和分攻击族指标
- 只在满足证据的情况下更新实验报告，不把目标写成结果

## 13. 明确不在本阶段实现

- 在线知识抓取或自动更新知识库
- 向外部防火墙、EDR、SIEM 或工单平台发送动作
- 自动修改检测阈值或安全规则
- 自动反馈训练
- 自动规划、工具自主调用、观察反馈与重新规划
- 声称 BEAST 或 AutoDAN-HGA 已通过冻结检测验证

## 14. 答辩表述边界

进阶任务的创新点不是 FTS5、RAG、Qwen、CPD 或官方安全框架本身，而是：

> 将 Token 级异常定位用于知识查询的隐私截断，在基础动作不可被改写的约束下绑定真实官方引用，并通过严格引用校验、确定性回退、人工确认工具和可验证证据包形成可审计的安全智能体处置链路。

对外只展示实际实验数据。外部系统尚未接入时，统一称为“平台内部处置闭环”，不称为“外部安全设备联动”。
