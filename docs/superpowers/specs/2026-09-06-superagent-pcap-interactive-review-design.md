# SuperAgent PCAP 互动复盘与任务恢复设计

## 目标

完善 `/super-agent` 的“PCAP 证据分诊”，让批量分诊完成后的互动回放真正解释 PCAP 证据，并让异常检测任务在切换 PCAP 页签或刷新页面后继续恢复显示。

## 范围

本次只修改 SuperAgent 的 PCAP 证据分诊体验：

- 保留“批量分诊”“数据勘察”“异常检测”三个现有名称。
- 保留单次最多处理 20 个文件的授权与资源边界。
- 不增加自动处理全部文件或自动签发下一批授权。
- 不修改 Prompt 检测、安全分析、在线防护、实验舱或 Token 侦探挑战。
- 不修改 PCAP 检测规则、阈值、Docker 隔离方式或任务并发策略。
- 不公开文件名、路径、IP、端口、载荷、原始请求或内容摘要。

## 批量分诊互动复盘

批量分诊任务仍一次处理用户授权范围内的一批 PCAP。任务完成后，现有“侦探证据回放”改为“批量分诊互动复盘”，使用该批次已经返回的公开 `captures` 数据，不发起第二次检测。

### 文件选择

- 默认选择当前批次第一条可用的 capture；如果批次为空，则显示明确空状态。
- 页面提供当前批次 capture 列表或前后切换控件，一次聚焦一份 PCAP 的公开证据。
- 用户切换 capture 时，角色访问进度重置，从第一位角色重新开始。
- “一次聚焦一份”只是结果讲解方式，不能描述为只检测了一个文件；标题和说明持续强调这是当前批次的逐文件复盘。

### PCAP 专属角色

互动复盘使用三个与现有公仔素材一一对应的 PCAP 角色：

1. 文件解析员：说明该 capture 的检查成功、失败或跳过状态、数据包数量和公开错误代码。
2. 流量分析员：展示该 capture 已返回的协议计数、明文应用协议、TLS/QUIC 加密传输或应用层不可见状态，并解释 `token_eligible`、`traffic_only` 或 `insufficient_evidence` 的证据能力边界。
3. 分诊队长：汇总该 capture 应保留公开元数据、继续异常检测、人工复核或重试；不得声称已发现或排除攻击。

角色按顺序解锁并支持点击回看，沿用现有互动操作模式和公仔资产。角色名称、说明和证据内容仅在 PCAP 互动复盘组件内改变；Token 侦探挑战的 `MascotTeam`、角色名称、关卡顺序、计分和结果不变。

### 结论边界

- 批量分诊只回答“文件是否形成可用网络证据”，不输出 SQL 注入等攻击判断。
- “检查成功”表示工具形成了有效报告，不表示流量安全。
- “仅流量证据”表示无法恢复应用语义，但仍可用于网络层研判。
- 失败和跳过分别显示原因，不能并入安全或无异常数量。
- 真正的攻击类型、Packet 异常区间和目的候选继续由“异常检测”页签负责。

## 异常检测任务恢复

### 根因

切换 PCAP 页签会卸载 `PcapDetectionWorkspace`，从而停止前端轮询。后端任务并未因此取消；现有代码已经保存检测任务 ID，却未在组件重新挂载时读取该 ID，所以返回页签后丢失任务显示。

### 恢复行为

- 异常检测启动后继续保存任务 ID 到 session storage。
- 重新进入“异常检测”或刷新页面时，先读取任务 ID，再向现有任务查询接口恢复快照。
- 恢复到 `queued` 或 `running` 时继续轮询；恢复到终态时直接显示已有结果。
- 切换到“批量分诊”或“数据勘察”只停止不可见组件的轮询，不调用取消接口，后台任务继续执行。
- 只有用户点击异常检测中的“取消”按钮才调用取消接口。
- 任务不存在、已过期、目标类型不匹配或返回无法验证时，清理失效 ID 并显示可重试提示，不能恢复成其他 PCAP 任务。
- 恢复请求和初次 overview 请求可以并行，但 UI 必须区分“正在恢复任务”和“异常检测不可用”。

## 组件边界

- `PcapMascotTeam` 及其 PCAP 调查状态负责批量分诊的逐 capture 互动复盘。
- `PcapEvidenceDesk` 只消费当前选中 capture 和批次公开报告，不读取私有字段。
- `PcapDetectionWorkspace` 独立负责异常检测任务 ID 的保存、恢复和轮询。
- `ChallengePage`、`MascotTeam`、Prompt/CPD 数据结构与接口不在修改范围内。

## 错误处理

- 批次没有 captures：互动复盘显示“本批次没有可回放文件”，不渲染空角色流程。
- capture 失败：解析员显示公开错误，后续角色说明证据不可用，队长建议重试。
- capture 跳过：说明该文件未形成新的检查结果，不复用其他 capture 的证据。
- 恢复请求失败：保留任务 ID供一次显式“重试恢复”；仅在确定 404、410、类型不匹配或响应无效时清理。
- 组件卸载后的异步响应不得更新已卸载状态。

## 测试

- PCAP 互动组件覆盖成功、失败、跳过、仅流量证据和证据不足。
- 覆盖默认 capture、切换 capture、角色进度重置和批次空状态。
- 验证互动复盘不会渲染另一个 capture 的协议或结论。
- 验证 Token 侦探挑战的角色、交互和测试保持不变。
- 异常检测页面覆盖运行中任务恢复、终态任务恢复、刷新恢复、404/410 清理、临时失败重试和目标类型不匹配。
- 验证切换 PCAP 页签不会调用取消接口，返回后继续轮询同一任务。

## 验收标准

1. 批量分诊完成后，用户能逐个查看当前批次内每份 PCAP 的公开证据。
2. 三个角色只解释 PCAP 解析、协议、证据能力和分诊建议，不沿用 Prompt/CPD 结论。
3. 互动复盘不把批量分诊描述为攻击检测，也不把成功解析描述为安全。
4. 切换 PCAP 页签或刷新页面不会使正在运行的异常检测任务丢失。
5. 只有显式取消操作会停止异常检测任务。
6. 三个 PCAP 页签名称、20 文件上限和现有隐私边界保持不变。
7. Token 侦探挑战没有视觉、行为、角色或数据变化。
