# PCAP 批量预检接入 SuperAgent 设计规格

## 1. 目标

将现有 PCAP 隔离预检能力作为受控工具接入现有 SuperAgent，使智能体能够在用户明确授权后发起批量网络证据分诊、读取脱敏摘要、形成可审计报告，并在证据满足条件时调用既有 Prompt 安全检测链。

本功能是增量能力。现有 Prompt 检测、Entropy-CPD、SuperAgent `investigate_and_respond` 任务、Token 侦探挑战、三名公仔、冻结样本、指标和安全动作不得发生行为变化。

## 2. 已确认范围

### 2.1 首版包含

- 在现有 `/super-agent` 页面增加独立的“PCAP 证据分诊”任务模式。
- 新增 SuperAgent objective：`triage_pcap_evidence`。
- 新增受限角色：`network_evidence_analyst`。
- 新增受控工具：`pcap_batch_triage`。
- 首次默认按文件大小从小到大处理 20 个合规文件。
- 单线程、逐文件、逐容器执行，每个容器无网络且只读挂载当前文件。
- 仓库外保存断点状态、私有匿名映射和脱敏批量报告。
- 在 PCAP 模式复用现有三名公仔的视觉语言、原地跳跃、点击引导和逐行汇报体验。
- 对网络证据、LLM 流量候选、Prompt 恢复和 Token 分析进行分级表达。

### 2.2 首版不包含

- 不修改 `/challenge` 的关卡、计分、状态机、旗帜或 Token 序号逻辑。
- 不把 PCAP 结果计入既有 jailbreak 准确率、召回率或冻结评测。
- 不绕过 TLS 或其他加密恢复应用层内容。
- 不将普通网络异常、HTTP 流量或 `token_eligible` 直接表述为 jailbreak 或异常 Token。
- 不上传 PCAP、载荷、报告、断点或私有映射到 GitHub。
- 不让模型直接读取 PCAP、文件路径、原文件名或原始载荷。

成功恢复 Prompt 后生成可玩 PCAP 特别关卡属于后续独立增量，不纳入本规格。

## 3. 选择的架构

采用“独立任务、共用 SuperAgent 编排器”。不把 PCAP 塞入现有 `investigate_and_respond`，也不建立第二套独立 Agent 平台。

```text
SuperAgent
├── investigate_and_respond        现有 Prompt 安全调查，行为不变
└── triage_pcap_evidence            新增 PCAP 证据分诊
    ├── coordinator                 检查授权并编排任务
    ├── network_evidence_analyst    解释脱敏网络证据
    ├── knowledge_analyst           核验证据等级与处置依据
    └── response_operator           形成受约束的处置报告
```

`response_operator` 仍不调用网络或子进程。Agent 只生成结构化工具请求；后端受控工具执行层验证 objective、授权令牌和参数后，才调用本机批量编排器。Docker 内部始终无网络。

不扩展现有 Prompt 实验舱的 `LabToolId`。PCAP 使用独立工具类型和独立结果类型，避免网络字段污染 Prompt 检测合同。

## 4. 用户界面

`/super-agent` 增加任务模式切换，默认仍为现有 Prompt 安全调查：

- `Prompt 安全调查`：现有页面和行为不变。
- `PCAP 证据分诊`：显示新增流程。

PCAP 模式包含：

1. **任务材料**：待处理数量、默认上限 20、是否存在续跑记录，不显示文件名和路径。
2. **授权确认**：只有用户点击“确认并开始”后才创建一次性任务授权。
3. **侦探小队**：复用 Guard、CPD、队长的现有公仔资产、原地跳跃、点击引导和逐行汇报视觉语言，不替换公仔。
4. **脱敏证据台**：协议聚合、内容可见性、LLM 候选数量、失败分类和 Token 分析资格。
5. **队长报告**：分别列出已证实、候选、未知和建议动作。
6. **私有映射提示**：只说明本机存在私有映射，不显示其内容或位置。

三名公仔在 PCAP 模式中的证据职责为：

- Guard：若已恢复 Prompt，则展示既有语义检测结果；否则明确展示“语义证据暂不可用”。
- CPD：只有 Prompt 已恢复、重新分词且模型实际完成 Entropy-CPD 后才展示结果；否则明确展示“无 Token 级证据”。
- 队长：汇总网络、语义和 CPD 三层可用证据，不填补缺失证据。

首版可新建 PCAP 模式专用视图组件并复用现有公仔资产和稳定组件接口，但不得修改 `/challenge` 的业务状态机。

## 5. 工具执行与授权

完整调用链：

```text
用户选择 PCAP 模式
→ 页面读取脱敏批次概况
→ 用户确认
→ 后端签发绑定当前任务的一次性授权
→ coordinator 请求 pcap_batch_triage
→ 工具执行层校验 objective、授权、处理上限和允许目录
→ PowerShell 批量编排器逐文件调用现有 inspect_pcap.ps1
→ 每个文件进入独立无网络容器
→ 返回脱敏批次摘要
→ network_evidence_analyst 研判
→ knowledge_analyst 核验
→ response_operator 生成报告
```

授权约束：

- 页面加载、模式切换和批次概况查询不能触发 PCAP 内容读取。
- 授权绑定任务 ID、允许目录、最大文件数和有效期，仅能消费一次。
- Agent 不得修改处理目录、扩大文件数或传入任意宿主机路径。
- 取消任务后授权立即失效，编排器完成当前单文件清理后停止调度。
- 未经重新确认，重试不能创建新批次；同一已授权任务内允许按断点规则重试单文件失败。

## 6. 批量编排与断点续跑

底层继续复用已通过安全审查的单文件 `inspect_pcap.ps1`。新增 PowerShell 批量编排器只负责选择、顺序执行、状态记录和脱敏汇总，不重新实现 PCAP 解析。

规则如下：

- 输入目录固定为配置的仓库外隔离目录。
- 只选择通过既有文件类型、大小和结构预检的 PCAP/PCAPNG。
- 首次默认选择最小 20 个文件。
- 单线程执行，任一时刻最多存在一个 PCAP 检查容器。
- 每次只读挂载当前文件，绝不挂载整个输入目录。
- 容器禁用网络并沿用现有资源、超时和输出限制。
- 已成功且安全摘要未变化的文件跳过。
- 上次失败的文件重试。
- 新增文件加入后续批次。
- 用户取消时保留已完成状态，下次从断点继续。

断点状态、脱敏报告和私有映射均存放于仓库外。公开摘要只使用匿名 `capture_id`；私有映射仅供工具层在本机定位文件，API、Agent、页面和导出报告均不得读取。

## 7. Agent 数据合同

Agent 只能接收：

- 匿名 `capture_id`
- 单文件处理状态
- 包数量与协议聚合
- `token_eligible`、`encrypted`、`network_only` 等能力分类
- 固定异常类别与计数
- 批次成功、失败、跳过和待处理数量
- 固定安全错误代码
- 已有检测链真实返回的语义、CPD 和处置摘要，仅限成功恢复 Prompt 后

Agent 不得接收：

- 原文件名、绝对或相对路径
- IP、端口、MAC、完整时间戳
- SHA 或其他可用于关联原文件的稳定标识
- 原始载荷、HTTP 正文、Prompt、攻击 suffix 或 Token 文本
- 模型内部思维过程
- Docker、PowerShell 或解析器的原始异常正文

队长报告引用工具生成的匿名证据 ID。未知引用、结构化输出解析失败或超时均退回确定性模板报告。

## 8. 证据升级与结论边界

证据只能沿以下路径升级：

```text
PCAP
→ 网络协议证据
→ LLM 流量候选
→ 恢复 Prompt
→ 模型重新分词并运行语义检测与 Entropy-CPD
→ Token 级结论
```

允许的主要状态：

| 状态 | 可声称结论 | 后续动作 |
|---|---|---|
| `network_only` | 普通网络分诊结果 | 保留网络证据，不进入 Token 检测 |
| `encrypted` | 应用层证据不可见 | 建议提供合规网关日志或解密条件 |
| `llm_candidate` | 符合 LLM API 流量候选特征 | 等待内容恢复，不声称 jailbreak |
| `prompt_recovered` | 已恢复完整可分析请求 | 送入既有 Prompt 检测链 |
| `token_analyzed` | 真实模型检测已经完成 | 可以展示 CPD、异常起点和 Token 级结论 |
| `analysis_failed` | 工具无法完成分析 | 返回固定错误分类并保留重试状态 |

`token_eligible` 仅表示协议条件允许继续解析，不等于 LLM 流量、Prompt 恢复或异常 Token。语义恶意但没有分布突变时仍由既有语义安全模块处置，不强行归因于 CPD。

## 9. 失败与恢复

- Docker 不可用：任务在工具调用前失败，返回环境错误，不影响其他 SuperAgent objective。
- 单文件损坏、不支持或超时：记录固定错误码，清理容器后继续下一个文件。
- 批次编排器异常退出：已原子写入的单文件状态保留，下次续跑。
- Agent 超时、未知证据引用或 JSON 无效：使用确定性模板报告。
- 用户取消：停止调度新文件，当前文件完成安全清理后结束。
- 页面刷新：从脱敏任务状态恢复，不重新处理已成功文件。
- 加密流量：终止应用层升级，报告证据不足，不尝试绕过加密。

任何 PCAP 失败不得改变现有 Prompt 检测服务健康状态、动作、事件或指标。

## 10. 安全与非回归约束

- 真实 PCAP 只在用户明确授权后由隔离工具读取。
- 工具运行时无网络、当前文件只读挂载、宿主机输入目录不整体暴露。
- 原 PCAP、载荷、私有映射、断点和输出报告不进入仓库。
- PCAP 模式关闭或未选择时，不增加现有 Prompt 请求的工具调用、延迟或事件。
- 现有 objective、工具合同、冻结数据和 API 默认响应保持不变。
- `/challenge` 首版零业务行为改动。
- PCAP 结论不改写既有 Prompt 检测动作或冻结指标。

## 11. 测试与验收

### 11.1 非回归

实现前记录现有后端、前端和构建基线；实现后运行相同完整套件。任何既有测试失败均视为 PCAP 接入不合格。

重点确认：

- `/analyze` Prompt 检测流程、返回字段和动作不变。
- `investigate_and_respond` 的角色、工具次数、事件上限和报告不变。
- `/challenge` 的关卡、三公仔、点击顺序、动画、旗帜、Token 序号、计分和隐私验证不变。
- 冻结样本结果和既有指标不变。

### 11.2 新增测试

- 未确认时 `pcap_batch_triage` 调用次数为零。
- 非 PCAP objective、失效授权、重复授权和越界路径均被拒绝。
- 首次默认选择最小 20 个文件并单线程执行。
- 单文件容器无网络、只读且只挂载当前文件。
- 成功文件跳过、失败文件重试、新文件加入、取消后续跑符合规则。
- Agent/API 敏感字段命中数为零。
- Agent 只引用真实匿名证据 ID；未知引用回退模板。
- Docker 缺失、文件损坏、超时、Agent 无效 JSON 和页面刷新均得到确定性处理。
- 只有 `token_analyzed` 能展示 CPD 和 Token 级字段。
- PCAP、报告、断点和映射均未被 Git 跟踪。
- 桌面与移动端任务模式、授权、事件链、三公仔汇报和错误状态可操作且无溢出。

### 11.3 完成定义

只有同时满足以下条件才可声明完成：

1. 全部既有测试和新增测试通过。
2. 真实 20 文件授权批次可以停止、续跑并处理新增文件。
3. SuperAgent 事件链能够审计角色、工具、时间、脱敏证据和最终动作。
4. Agent、API、页面和导出报告均未暴露禁止字段。
5. PCAP 结果未被错误表达为 Entropy-CPD 或异常 Token。
6. Git 中不存在 PCAP、PCAPNG、报告、断点或私有映射。

## 12. 设计理由

独立 objective 和数据合同使 PCAP 成为 SuperAgent 的真实工具能力，而不是孤立脚本；共用编排器、事件链和原三公仔视觉语言使演示保持一体化。逐文件无网络容器、明确授权和仓库外状态限制未知 PCAP 的影响范围。证据升级链避免把网络层候选冒充 Token 级创新。首版不修改 `/challenge`，优先保护已经完成并验证的基础页面和游戏体验。
