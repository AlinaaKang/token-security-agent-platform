# 安全分析与在线防护差异呈现设计

## 目标

让用户在 `/analyze` 页面选择工作模式时立即理解两种策略的差异，并在检测完成后看到当前模式对本次处置产生的具体影响，无需对同一 Prompt 重复检测。

## 范围

本次只调整前端信息呈现。保持后端融合规则、分析请求与响应结构、检测次数、知识增强、审计、阈值和隐私边界不变。

## 页面设计

### 模式选择

保留现有工作模式控件，将两个选项改为带简短说明的分段选择：

- 安全分析：用于研究与判断；单独出现 CPD 异常时按拦截展示。
- 在线防护：用于生产网关；单独出现 CPD 异常时转人工复核，语义服务不可用时执行故障安全复核。

选中状态同时使用文字、边框和背景表示，不只依赖颜色。

### 策略差异预览

模式控件下方显示一个紧凑说明区，只列出会产生不同动作的条件：

| 条件 | 安全分析 | 在线防护 |
| --- | --- | --- |
| 仅 CPD 异常 | 拦截 | 人工复核 |
| 语义不可用、CPD 正常 | 降级放行 | 人工复核 |
| 语义不可用、CPD 异常 | 拦截 | 人工复核 |

语义危险、语义争议和双路正常在两种模式下结果相同，不占用常驻空间；在可展开说明中补充完整规则。

### 检测结果中的模式影响

检测完成后，在融合处置节点下方增加“模式影响”区域，显示：

- 当前模式与当前动作；
- 在相同语义状态和 CPD 状态下，另一模式会采取的动作；
- 如果两种模式动作相同，则明确显示“切换模式不会改变本次处置”。

对照动作由前端使用已返回的 `semantic_severity` 和 `detector_status` 通过纯函数计算，不重新发送 Prompt，不发起第二次模型调用，也不修改服务端结果。

## 组件与数据流

新增一个无副作用的策略对照函数，输入为工作模式、语义状态和 CPD 是否命中，输出当前动作、另一模式动作及公开说明。该函数的分支必须与后端 `EvidenceFusionPolicy` 保持一致，并通过表驱动测试锁定全部组合。

`AnalyzePage` 在发起请求时同时保存本次提交的模式快照，并将该快照传给结果区域。用户随后切换控件只影响下一次检测，不会改变旧结果的模式标签。结果区域只在已有分析结果时显示模式影响，不缓存 Prompt，不写浏览器存储，也不触发 API。

## 异常与边界

- 检测尚未完成时不显示假定的本次模式影响。
- 语义状态不可用时明确使用“语义服务不可用”措辞，不把降级放行描述为安全。
- 未识别状态不猜测对照动作，显示“无法形成模式对照”。
- 响应中的实际 `decision` 仍是权威结果；若前端对照与实际结果不一致，显示“策略版本不一致”，不覆盖实际动作。
- 页面不显示原始 Prompt、Token 文本、模型原始输出或隐藏推理。

## 响应式与无障碍

桌面端使用紧凑横向分段控件和三行策略预览；手机端改为单列，保证最长文字不溢出。模式选项继续支持键盘操作和 `aria-pressed` 状态；动作差异同时显示明确文字。

## 验收标准

1. 用户在提交前能看到两种模式的定位和三类不同策略。
2. 同一条检测结果能显示当前模式动作与另一模式对照动作。
3. 打开说明或切换模式不会自动提交检测。
4. 已完成结果在切换模式后仍标记其实际运行模式，不能把旧结果误认为新模式结果。
5. 全部策略组合与后端融合规则一致。
6. 现有 Prompt、PCAP、Challenge、Lab、审计和 API 测试保持通过。
