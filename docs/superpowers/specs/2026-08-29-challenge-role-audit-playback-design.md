# 挑战任务角色式逐行审计回放设计

## 目标

将 `/challenge` 的互动调查升级为角色式逐行审计回放：三名公仔保持原有站位，当前需要操作的角色原地短跳，用户点击后逐行查看该角色的真实脱敏证据；汇报完成后提示转移到下一位。已完成角色可以随时回看，但回看不倒退流程、不重新运行检测。

该体验借鉴逐行展开的阅读节奏，但页面必须使用“可审计决策过程”或“检测结果回放”表述，不展示或声称展示模型隐藏 CoT。

## 范围与边界

- 仅调整挑战页前端的角色状态、回放组件、动效、引导和相关测试。
- 继续消费现有已完成的 `LabRunResult`，不新增 SSE、WebSocket、模型调用、后端接口、数据库或遥测。
- 逐行内容只能由现有结构化字段确定性生成，不调用 LLM 编写解释。
- 不展示或派生原始 Prompt、攻击 suffix、Token 文本、模型词表 Token ID、检索词、原始模型输出、Guard 原始输出或隐藏 CoT。
- 不改变检测结果、融合动作、CPD 起点、评分规则、关卡定义或 `/analyze`、`/lab`、`/super-agent` 行为。
- 保留“互动调查”和“自动演示”两种调查方式。

## 方案选择

采用角色汇报式方案：公仔负责选择和进度引导，中央证据台负责逐行展示该角色的公开证据。

不采用统一时间线，因为它会弱化三名角色与证据所有权的关系；不采用公仔旁气泡，因为语义类别、CPD 指标和队长总结在移动端难以稳定容纳。

## 交互状态

调查进度与当前查看对象分离：

- `nextRole`：下一位尚未完成汇报的角色。
- `selectedRole`：中央证据台当前展示的角色，可以是下一位或已完成角色。
- `presentingRole`：正在进行首次逐行回放的角色；同一时间最多一个。
- `visitedRoles`：已经完成首次汇报的角色集合。

首次点击 `nextRole` 时：

1. 角色保持原位并停止等待态跳动。
2. 中央证据台从第一行开始逐行展示该角色报告。
3. 回放完成后将角色加入 `visitedRoles`。
4. 下一位角色变为 `nextRole`，开始原地短跳并显示点击提示。

点击 `visitedRoles` 中的角色时：

- 立即显示该角色的完整报告并标记为当前查看对象。
- 不修改 `nextRole`、`visitedRoles`、答题解锁状态或检测结果。
- 不重新播放逐行动画，避免误导用户认为系统重新执行了检测。

未来角色保持禁用。队长首次汇报完成后调查进度变为完成，答题区解锁；三名角色仍可点击回看。

## 公仔表现

- 三名角色始终位于各自网格位置，删除互动和自动模式中的横向 `translateX` 位移。
- 只有 `nextRole` 原地进行低幅度双跳，角色容器尺寸保持不变，避免布局抖动。
- `nextRole` 上方显示带向下箭头的提示：“下一步：点击语义侦探 / 曲线侦探 / 小队队长”。箭头使用 Lucide 图标。
- 已完成角色显示勾选和“已汇报，可回看”。
- `selectedRole` 使用明确描边和 `aria-pressed="true"`，与“已完成”状态分别表达。
- 完成整关时保留一次短暂庆祝；证据分歧仅在提交研判后的揭晓阶段显示。
- `prefers-reduced-motion: reduce` 下关闭跳跃、庆祝和过渡，以静态描边、图标和文字保留全部状态信息。

## 逐行报告

新增纯函数，将 `LabRunResult` 与角色映射为结构化公开行。每一行包含稳定 ID、简短标签、公开值和状态，不包含自由文本推理。

语义侦探按顺序显示：

1. 语义检测已完成。
2. 归一化语义等级。
3. 归一化风险类别；无类别时显示“未命中风险类别”。
4. 公开模型版本与服务端检测耗时。

曲线侦探按顺序显示：

1. Token 观测已完成。
2. CPD 是否发现分布异常候选。
3. CPD 分数与阈值。
4. 异常起点 Token 序号；不存在时显示“不适用”。
5. 固定声明“分布异常只代表候选信号，不单独证明恶意”。

小队队长按顺序显示：

1. 已收到语义与 CPD 两路公开证据。
2. 两路关系：一致、分歧或证据不足。
3. 固定声明“提交研判前不展示系统动作”。
4. 调查证据已汇总，可以进入玩家研判。

逐行区域使用有序列表和 `aria-live="polite"`。默认每 `420ms` 展示一行；这只是界面回放间隔，服务端耗时继续显示实际 `latency_ms`。区域固定显示：“这是已返回检测结果的逐行回放，不代表模型正在实时推理，也不包含隐藏思维链。”

首次回放提供“立即显示完整汇报”命令。点击后同步显示剩余行、完成当前角色并解锁下一位。减少动态效果模式直接显示完整报告。

## 自动演示

自动演示继续使用已返回的 `LabStage[]`，但公仔仅在原位跳动。现有 `700ms` 阶段回放和“跳过回放”保留，并继续明确说明它不是实时推理。

互动调查的角色逐行回放与自动演示不同时运行。切换调查方式只允许在挑战设置阶段，进入挑战后沿用选定模式。

## 数据流

```text
现有 LabRunResult
  -> 确定性 role audit line builder
  -> 首次点击角色
  -> 本地计时器逐行显示
  -> 回放完成事件
  -> investigation reducer 推进 nextRole
  -> 下一位公仔原地提示
```

所有状态仅存在 React 内存中。刷新、退出、重试和下一关都必须清除计时器、当前查看角色、已完成角色和逐行回放位置。

## 失败与降级

- 语义证据不可用：显示规范化的“语义证据不可用”，仍允许完成该角色汇报。
- CPD 信号为空或无起点：显示“未发现分布候选”或“定位不适用”，不伪造数值。
- 知识阶段不可用：不阻断三角色调查和答题。
- 本关请求失败：沿用固定错误文案，不显示异常正文；重试后从语义侦探重新开始。
- 计时器在换关、重试、退出、卸载或结果对象替换时必须取消，旧回放不得写入新关卡状态。

## 可访问性与响应式

- 公仔继续使用原生 `button`；未来角色为 `disabled`，已完成角色可键盘回看。
- 引导文字不能只依赖动画或颜色，并通过角色状态文本与 `aria-describedby` 暴露。
- 逐行列表新增内容使用礼貌播报，不把整块报告设置为每行都重新朗读。
- 桌面保持三列阵容；移动端保持三名角色同屏或在既有断点下稳定缩放，不产生横向页面溢出。
- 公仔、提示、报告文字设置稳定尺寸和换行规则，跳跃不能改变网格高度。

## 测试与验收

纯逻辑测试：

- 三类角色只从允许字段生成固定顺序的公开行。
- 不可用证据、无类别、无 CPD 起点和无服务端耗时有确定性降级文本。
- 首次汇报完成后才推进下一位；回看不推进或倒退进度。
- 重试、换关、退出和结果替换恢复初始状态。

组件测试：

- 当前角色原地跳动且无横向位移类；下一位提示与禁用边界正确。
- 首次点击逐行增加内容，跳过后立即完成；已完成角色重复点击显示完整报告。
- 回看旧角色时下一位仍保持等待提示，答题区不关闭。
- 减少动态效果时无动画并立即显示完整报告。
- 计时器在跳过、重置和卸载后为零。
- DOM 和可见文本不包含隐私禁止字段或隐藏 CoT 宣称。

浏览器验收：

- 在 `1440x900` 和 `390x844` 完成一轮互动调查。
- 三名公仔中心横坐标在整个调查期间保持稳定。
- 当前角色只有纵向原地跳跃；提示依次转移到三名角色。
- 完成三次汇报后可以按任意顺序回看，调查进度和答题区保持不变。
- 自动演示、跳过回放、减少动态效果、页面无横向溢出和零控制台错误继续通过。
- 受保护样本页面不出现 Prompt、suffix、Token 文本、Token ID 或原始模型输出。

## 完成标准

- 用户能按语义侦探、曲线侦探、小队队长的顺序完成角色式逐行审计回放。
- 三名公仔不再移动到中间，只有当前下一位在原地跳动。
- 明确提示用户点击下一位，已完成角色可重复回看。
- 页面清楚声明这是已返回结果的可审计回放，不是实时模型思考或隐藏 CoT。
- 基础检测、评分、隐私边界、两种调查方式和其他页面无回归。
