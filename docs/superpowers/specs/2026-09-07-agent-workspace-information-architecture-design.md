# 安全智能体工作区信息架构设计

## 目标

将当前混合的安全智能体、Prompt 工具、PCAP 工具和智能体资源重新组织为清晰的任务入口。用户应能从左侧直接判断自己正在创建 Prompt 调查还是 PCAP 调查，并在各自入口下恢复对应的历史任务。底层仍是同一个 Token Security 安全智能体，以保留统一规划、工具调用、反馈重规划和跨域案件能力。

## 左侧导航

左侧导航按以下顺序组织：

1. `安全对话`
   - `Prompt 安全调查`
   - `PCAP 数据集调查`
2. `Prompt 专业工作区`
   - `Prompt 安全分析`
   - `Prompt 攻防实验`
   - `Prompt 评测中心`
   - `Token 侦探挑战`
3. `PCAP 专业工作区`
   - `PCAP 上传检测`
4. `智能体资源`
   - `安全知识库`
   - `数据连接器`
   - `调查报告`

`检测技能`不再作为资源入口展示。它与安全智能体的内部规划能力重复，剧本仍可由智能体后端使用，但不占用独立导航位置。`安全事件`继续保留在安全案件区域，用于查看脱敏检测事件，不混入对话历史。

## 两类安全对话

两类对话共享同一条 `/super-agent` 路由，通过 `mode=prompt|pcap` 表达工作模式：

- `/super-agent?mode=prompt` 创建 Prompt 安全调查。欢迎区提供 Prompt 检测、安全知识问答和跨域演示示例；文本输入是主要操作。
- `/super-agent?mode=pcap` 创建 PCAP 数据集调查。欢迎区提供 PCAP 文件上传、批量数据集调查和 Packet 解释示例；PCAP 上传是主要操作。

每个入口下面显示自己的“新建对话”和最近任务列表。PCAP 类型任务归入 PCAP 列表；其余文本发起的 Prompt、知识问答和跨域调查归入 Prompt 列表。点击历史任务时 URL 同时保留任务 ID 和所属模式。切换模式只更换当前工作区和历史列表，不调用取消接口，也不停止后台 Agent 或 PCAP mission。

新建 Prompt 对话会清空当前中央对话并保留 `mode=prompt`；新建 PCAP 对话会清空当前中央对话并保留 `mode=pcap`。历史任务、消息时间和浏览器本地保存的原始 Prompt 继续按现有规则恢复。

## 对话呈现

中央对话采用明确的双边布局：

- Token Security 智能体消息靠左，智能体图标位于消息左侧。
- 用户消息靠右，用户图标位于消息右侧。
- 名称、发送时间、证据范围和正文随消息一同对齐。
- 长 Prompt、长文件名和中文连续文本必须换行，不能产生横向滚动。

输入框保持三行左右的默认高度，不允许用户拖成占据整个页面的大输入框。内容超过上限后在输入框内部滚动；桌面和手机均保留发送键及 PCAP 添加按钮的稳定位置。

## 专业工作区拆分

`/lab`继续复用现有实现，但入口使用 `surface=prompt|pcap` 固定内容：

- `/lab?surface=prompt`只显示 Prompt 攻防实验，不再显示 Prompt/PCAP 切换控件。
- `/lab?surface=pcap`只显示 PCAP 上传检测，不再显示 Prompt/PCAP 切换控件。
- 旧的 `/lab`默认重定向或归一化为 Prompt 实验，以保持旧链接可用。

`/analyze`、`/evaluation`和`/challenge`属于 Prompt 专业工作区。检测算法、阈值、冻结评测数据、Token 侦探挑战规则和 PCAP Docker 隔离路径不变。

## 右侧检查器

只有真实的安全对话页面显示右侧案件检查器：

- Prompt 模式显示 Prompt 专用检查器。
- PCAP 模式显示 PCAP 专用检查器。
- 跨域文本任务继续显示通用案件检查器。

安全事件、Prompt 专业工作区、PCAP 专业工作区、Token 侦探挑战和智能体资源页面均不渲染右侧检查器。桌面端主页面自动占用释放出的宽度；手机端这些页面不显示“打开检查器”按钮。资源页面的内容只在中央显示，不再保留右侧“资源说明”。

## 视觉与响应式

侧栏保持现有浅蓝体系，并以全高背景覆盖视口。导航链接占满可用宽度，激活背景覆盖完整行，不因图标、长标题或滚动区域产生断层。两类安全对话及两个专业工作区使用清晰的小组标题，不通过额外卡片制造层级。

桌面端安全对话使用“240px 侧栏 + 弹性中央区 + 360px 检查器”；无检查器页面使用“240px 侧栏 + 弹性中央区”。1100px 以下检查器变为抽屉，760px 以下导航变为抽屉、内容单列、主要触控目标不小于 44px。

## 状态与边界

- 模式只决定入口、示例、历史任务分组和检查器呈现，不扩大后端权限。
- Prompt 与 PCAP 读取仍需要现有明确授权。
- 切换页面或模式不会取消任务；只有明确取消操作才调用取消接口。
- PCAP 文件仍只进入本机 `/pcap-api` 与隔离 Docker，不上传 AutoDL。
- 原始 Prompt 不进入服务器 SQLite、事件、证据或报告，浏览器本地历史策略保持不变。
- 资源入口删除不等于删除后端剧本或检测能力。

## 测试与验收

自动化测试应覆盖：

- 左侧导航只显示三个资源入口，并正确显示两类安全对话和两个专业工作区。
- Prompt 与 PCAP 新建入口、历史任务过滤、URL 模式和刷新恢复。
- 模式切换不调用任务取消接口。
- Prompt/PCAP 实验入口只渲染对应内容。
- 只有安全对话页面存在案件检查器和移动端检查器按钮。
- 用户消息右对齐且头像在右，智能体消息左对齐且头像在左。
- 输入框不能纵向拖拽且具有最大高度。
- 侧栏与激活背景覆盖完整可用区域。

完成后运行完整前端测试、生产构建、差异检查和界面规则扫描，并分别检查桌面与手机上的 Prompt 对话、PCAP 对话、Prompt 实验、PCAP 上传和资源页面。
