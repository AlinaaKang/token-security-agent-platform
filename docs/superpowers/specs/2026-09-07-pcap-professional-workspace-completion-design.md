# PCAP 专业工作区补齐设计

## 目标

将 PCAP 专业工作区补齐为与 Prompt 专业工作区同样清晰的四项能力，同时避免重复“PCAP 数据调查”的上传检测流程。专业工作区负责认识数据、攻防实验、评测验证和互动训练；真实文件调查继续只在“安全对话 > PCAP 数据调查”中完成。

## 信息架构

PCAP 专业工作区按以下顺序显示：

1. `PCAP 流量画像`：对授权数据集抽取 20 个分层样本，展示协议、包数量、持续时间、明文/加密和序列候选的聚合画像。
2. `PCAP 攻防实验`：运行内置、隔离的 PCAP 攻击与防护演示。
3. `PCAP 评测中心`：展示冻结的脱敏回归集指标、定位命中率、误报率和规则/行为/融合消融。
4. `PCAP 侦探挑战`：使用内置脱敏关卡，让用户标记异常 Packet、攻击类型和目的并获得评分。

`PCAP 数据调查`保留在安全对话区，不在专业工作区增加“PCAP 上传检测”或其他同义入口。

## PCAP 流量画像

复用现有 `PcapReconWorkspace` 和 PCAP reconnaissance API，整理为独立路由 `/pcap-profile`。画像只返回聚合统计，不显示文件路径、文件身份、IP、端口、原始载荷或 Prompt，不执行攻击检测，也不把协议候选描述为大模型流量证明。

页面包括：

- 可选文件数量、固定抽样上限和抽样方法；
- 四分位覆盖；
- Packet 数量分布；
- 流量持续时间分布；
- 协议出现样本数；
- 明文、加密和序列候选统计；
- 数据勘察阶段、授权确认、运行、失败重试和刷新恢复状态。

## PCAP 评测中心

新增独立路由 `/pcap-evaluation`。评测中心只展示版本化、脱敏、可复现的回归结果，不在打开页面时扫描用户 PCAP，也不把内置合成回归结果宣称为真实生产准确率。

评测内容包括：

- 样本数、Precision、Recall、F1、误报率和 Packet 区间定位命中率；
- `rule_only`、`behavior_only`、`fused` 三种方法的消融对比；
- 数据集类型、版本、生成时间和真实性说明；
- 明确说明“内置脱敏回归用于验证检测链路，不代表真实网络总体效果”；
- 报告不可用时显示缺失原因和恢复建议，不显示伪造的 0% 或 100%。

后端复用 `app.evaluation.pcap_detection` 的模型与计算函数，加载一个版本化的公开脱敏回归清单，返回严格响应模型。清单只包含标签、预期 Packet 区间和已脱敏的结构化证据，不包含文件名、路径、地址、载荷或用户数据。

## 导航与引导

- 左侧 PCAP 专业工作区新增“PCAP 流量画像”和“PCAP 评测中心”，最终与 Prompt 专业工作区同为四项。
- 两个页面拥有独立的“本页引导”步骤和完成状态。
- 页面使用当前浅蓝色工作台视觉体系，标题、指标和解释文字保持现有操作型界面的紧凑层级。
- 桌面与移动端均不得出现横向溢出或遮挡发送按钮、本页引导和导航抽屉。

## 验收标准

- PCAP 专业工作区显示流量画像、攻防实验、评测中心和侦探挑战四个入口。
- 不出现独立“PCAP 上传检测”入口。
- 流量画像能够授权运行、恢复任务并展示现有聚合统计。
- 画像页面不显示原始文件身份、地址、载荷或攻击结论。
- 评测中心展示版本化结果、五项核心指标和三种消融方法。
- 评测页面明确区分内置脱敏回归与真实生产效果。
- 评测报告缺失或无效时显示不可用状态，不制造指标。
- 两个新路由的引导内容可用，导航选中状态准确。
- 前后端测试、生产构建以及桌面和移动视觉检查通过。

## 测试策略

- 后端单元测试验证回归清单隐私字段、指标计算和版本信息。
- API 集成测试验证成功响应、报告缺失和报告校验失败。
- 前端页面测试验证指标、消融、真实性声明和不可用状态。
- 导航测试验证四个 PCAP 专业入口且无重复上传入口。
- 引导测试验证两个路由具有独立非空步骤。
- 运行生产构建并在 1440×900 与 390×844 视口检查布局。
