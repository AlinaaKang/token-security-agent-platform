# 可审计 ReAct 推理链视觉化设计

## 1. 目标

在现有 `/super-agent` 页面中，将偏事件日志形态的“命令轨道”升级为评委能够快速理解的可审计推理链。页面清楚表达证据如何经过规则形成计划、动作和闭环结果，但不展示或伪造模型隐藏思维过程。

本设计同时包含一个独立的小型体验修正：在 `/challenge` 游戏曲线中，仅为玩家选中的旗帜提供 Token 序号提示。

基础检测、CPD 算法、融合决策、工具执行顺序和后端任务状态机均不改动。`/analyze`、`/lab`、`/challenge` 的既有主流程必须保持稳定。

## 2. 方案选择

### 方案 A：逐步证据卡

每条事件展开为独立的“观察、依据、结论”卡片。细节完整，但页面仍接近纵向审计日志，整体因果关系不够醒目。

### 方案 B：横向因果线路

使用一条横向流程线展示所有节点，点击节点查看详情。全局路径清楚，但十二条事件在窄屏中容易拥挤，移动端需要折行或横向滚动。

### 方案 C：因果总览与证据详情结合（采用）

顶部使用五阶段因果总览，底部显示当前节点的结构化详情。运行时自动跟随最新事件，任务完成后允许点击任意节点复盘。该方案兼顾演示辨识度、审计深度和响应式适配。

## 3. 信息架构

原“命令轨道”区域改名为“可审计推理链（ReAct）”，由两个清晰边界的组件组成：

1. `ReasoningChainOverview`：展示五个阶段、状态、连接关系和当前选中节点。
2. `ReasoningEvidenceDetail`：展示选中节点的角色、观察证据、适用规则、结论或动作、工具及回执。

五阶段固定为：

1. 观察证据；
2. 应用规则；
3. 调整计划；
4. 执行动作；
5. 验证结果。

阶段顺序表达因果结构，不替代原始事件顺序。每个阶段可容纳一条或多条真实事件；阶段内事件仍按 `sequence` 排序。原有角色状态、任务闭环摘要、工具回执和内部仿真边界声明继续保留。

## 4. 事件映射

推理链只读取现有公开事件字段：

- `phase`；
- `actor`；
- `status`；
- `summary`；
- `evidence_codes`；
- `tool_id`；
- `sequence`。

映射规则固定且可测试：

| ReAct 视觉阶段 | 事件来源 |
| --- | --- |
| 观察证据 | `observe` 事件以及首次基础检测完成的公开 `act` 事件 |
| 应用规则 | 初始 `plan` 事件和包含公开策略依据的协调员事件 |
| 调整计划 | `replan` 事件 |
| 执行动作 | 带 `tool_id` 的 `act` 事件 |
| 验证结果 | 工具回执观察及 `complete` 事件 |

详情区不使用模型生成的新文本。`summary` 作为公开结论摘要，`evidence_codes` 经过现有标签映射后分别进入观察证据或适用规则区域。无法归类的依据保留其现有脱敏标签，不进行猜测。

当某个阶段没有事件时，节点显示“等待证据”。字段缺失时详情区显示“暂无可公开证据”，不得补写推理内容。

## 5. 交互状态

任务运行和恢复时默认启用“跟随最新进度”：

1. 已经由 API 返回的事件按 `sequence` 依次短暂入场；
2. 当前节点自动选中，详情区同步更新；
3. 动画不显示“模型正在思考”等未经证实的中间状态；
4. 新事件全部展示后停留在最终闭环节点。

用户点击或键盘选择任意已有节点后，进入手动复盘状态，详情区保持在所选节点。界面提供“跟随最新进度”按钮，使用户可返回自动跟随。任务完成后所有已有节点均可复盘。

节点必须支持键盘聚焦和激活，并通过文本、图标和颜色共同表达状态。等待、成功、失败和选中状态不能只依赖颜色区分。

## 6. 视觉语言

页面继续使用现有墨绿、琥珀和红色安全运营台风格：

- 墨绿：已核验的观察、规则和成功动作；
- 琥珀：唯一的重规划视觉重点；
- 红色：阻断结果、工具失败或降级闭环；
- 中性灰：尚无事件的等待阶段。

桌面端使用横向五阶段线路和下方详情区。移动端在不改变阅读顺序的情况下转为纵向线路，禁止依赖横向滚动。连接线和方向箭头表达因果方向，不增加装饰性动画。

在 `prefers-reduced-motion: reduce` 下关闭节点入场、连线推进和状态切换动画。

## 7. 失败与边界状态

- 任务失败或超时时，链路停在最后一条真实事件，并显示明确的失败或降级状态。
- 工具失败仍展示已有工具回执，不渲染完整成功闭环。
- 安全任务允许零工具结束；视觉层不得为了显得复杂而创建虚假动作节点。
- 刷新恢复使用现有脱敏 mission ID 和任务响应，恢复后的节点、详情和闭环结果必须一致。
- 页面只声明“结构化可审计决策轨迹”，不得声明展示完整隐藏 CoT。

## 8. 隐私约束

推理链不得展示、保存或派生以下内容：

- 原始 Prompt；
- 攻击 suffix；
- Token 文本或 Token ID；
- 检索词；
- 模型原始输出；
- 隐藏推理过程；
- 密钥、私人路径或外部系统数据。

可展示 CPD 返回的脱敏异常起点序号，因为它是现有公开检测证据。该序号表示曲线中的位置，不是模型词表 Token ID；不得由此恢复对应 Token 文本。

## 9. 游戏旗帜 Token 序号

`ChallengeSignalPicker` 已以真实 `signal.index` 绑定每个旗帜。体验修正遵循以下规则：

- 未选中的旗帜不常驻显示 Token 序号；
- 玩家选中旗帜后，仅在该旗帜悬停或键盘聚焦时显示 `Token #<signal.index>`；
- 提示应使用可访问的 tooltip 语义，鼠标和键盘获得同等信息；
- 提示不得遮挡主要曲线或改变旗帜位置；
- 提交后的“玩家起点”和“CPD 起点”继续使用现有真实序号；
- 只展示曲线位置序号，不展示 Token 文本、模型词表 Token ID 或其他模型内部信息。

该修正仅改变曲线选择器的提示层，不改变起点选择、计分或提交逻辑。

## 10. 测试与验收

前端组件测试至少覆盖：

1. 现有事件正确映射到五阶段；
2. 多事件阶段保持 `sequence` 顺序；
3. 自动跟随选择最新真实节点；
4. 点击和键盘操作可进入手动复盘；
5. “跟随最新进度”恢复自动选择；
6. 缺失字段显示确定性回退文案；
7. 安全零工具任务不出现虚假工具动作；
8. 失败工具和降级闭环状态正确显示；
9. 刷新恢复后选中与展示状态合理；
10. 只有选中的挑战旗帜在悬停或聚焦时显示真实 Token 序号。

完成实现后运行完整前端与后端测试、Vite 构建和浏览器回归。Playwright 至少检查 `1440x900` 与 `390x844`，验证无横向溢出、无文本遮挡、控制台无错误，并回归 `/analyze`、`/lab`、`/challenge` 和 `/super-agent`。

## 11. 完成标准

评委无需阅读长事件日志，即可从第一屏辨认出“观察证据到验证结果”的智能体闭环；点击任意节点可以核对该结论来自哪个角色、哪些公开依据和哪个工具回执。所有展示均可追溯到真实 API 字段，且不泄露或伪造模型隐藏思维过程。
