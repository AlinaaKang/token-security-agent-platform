# 本地安全知识 RAG 进阶任务设计

日期：2026-08-26

## 1. 目标与赛题范围

本设计实现赛题中占 20 分的进阶任务“领域知识增强与工具扩展”，不改变已经完成的 70 分基础任务判定行为。

第一阶段在现有 Qwen3Guard 与 Entropy-CPD 工作流后增加离线、版本化的安全知识库、本地检索和有依据的研判报告。第二阶段增加受控的官方来源在线更新，同时保留离线运行和人工审批能力。

进阶任务提升的是解释深度、来源可追溯性和处置建议完整性。在建立独立冻结语义评测前，不声称它提高了语义分类准确率。

## 2. 已确定的产品决策

- 第一阶段断网时可以完整运行。
- 第二阶段采用“本地已批准快照 + 在线待审核增量”。
- RAG 证据不得改变现有 `allow`、`review` 或 `block` 动作。
- 现有 API 客户端保持兼容，只有显式设置 `knowledge_mode` 才启用知识增强。
- 官方资料只转述为简短知识卡，不把第三方网页全文复制进仓库。
- Prompt、suffix、Token 文本、模型原始输出和私有资料不得进入 Git、SQLite、报告、截图或应用日志。
- 知识检索与报告生成在基础任务已经完成判定后执行；知识层失败不能导致基础检测不可用。

## 3. 官方来源基线

首个批准快照使用以下官方来源：

- OWASP GenAI Security Project：大模型应用风险与缓解措施。
- MITRE ATLAS：对抗机器学习战术与技术。
- NIST AI Risk Management Framework 及生成式 AI 指南：治理、测量和风险处置。

每张知识卡记录发布方、官方标题、规范 URL、来源版本或发布日期、核验日期、许可证或使用说明，以及规范化知识卡内容的 SHA-256。CPDonline 仍然是 CPD 实现与原始基准数据的唯一署名来源。

## 4. 总体架构

```text
AnalysisRequest
  -> 现有 Qwen3Guard 语义评估
  -> 现有 Qwen2.5 Token 观测与 Entropy-CPD
  -> 现有固定证据融合与最终动作
  -> knowledge_mode=off：返回不变的基础结果
  -> knowledge_mode=evidence/report：
       SafeQueryBuilder
         -> 仅在内存中临时读取 Prompt
         -> CPD 有起点时移除可疑后缀
         -> 长度限制与敏感值脱敏
         -> 生成净化查询和固定安全标签
       LocalKnowledgeRetriever
         -> 标签路由
         -> SQLite FTS5 排序
         -> 返回 Top-K 规范化知识证据
       evidence：只附加检索证据
       report：
         GroundedReportGenerator
           -> 只接收规范化检测事实与已检索知识卡
           -> 严格结构化输出
           -> 引用校验
           -> 任一失败时使用确定性模板
  -> 返回隐私安全的 API 结果与规范化审计元数据
```

第一阶段不引入向量数据库和额外 Embedding 模型。当前知识库规模较小，安全标签本身已经是高质量检索信号；SQLite FTS5 更便于离线部署、复现、检查和审计。只有后续评测证明语义召回存在明确缺口时，第二阶段才增加本地 Embedding 重排。

## 5. 信任边界

### 5.1 原始 Prompt 权限

只有现有检测模型和 `SafeQueryBuilder` 可以读取原始 Prompt。查询构造器只在单次请求的局部变量中使用它，并返回净化查询；不得记录、缓存、持久化或通过 API 暴露 Prompt。

CPD 给出异常起点时，查询构造器在生成检索词前删除可疑后缀；没有起点时，使用经过同样长度限制和脱敏处理的完整 Prompt。查询内容始终被视为数据，不得拼接成可执行的系统指令。

### 5.2 检索器权限

检索器只接收：

- 净化后的查询文本；
- 语义等级与类别；
- CPD 状态与是否存在起点；
- 融合原因与最终动作；
- 工作模式；
- 可选的受保护演示攻击族。

检索器不能调用工具、执行文本、访问任意文件路径或更新索引。

### 5.3 报告生成器权限

报告生成器不得接收原始 Prompt、Guard 原始输出、suffix 或 Token 文本。它只接收规范化检测事实和本次实际检索到的知识卡。所有引用 ID 必须属于本次检索结果。

### 5.4 持久化边界

SQLite 审计只允许新增知识快照版本、知识模式、检索状态、知识卡 ID、报告状态和知识层延迟。禁止保存检索查询、知识卡正文、模型原始输出或用户内容。

## 6. 数据契约

### 6.1 知识卡

```text
knowledge_id: 稳定且非空的标识符
title_zh: 简洁中文标题
risk_domain: 固定风险领域枚举
semantic_categories: 零个或多个现有 Guard 类别
detector_tags: cpd_candidate、no_token_anomaly 等固定标签
fusion_tags: 零个或多个现有融合原因
attack_families: 可选的固定演示攻击族
summary: 忠于来源的简短转述
indicators: 规范化识别依据列表
recommendations: 有序处置建议
source.publisher: OWASP、MITRE 或 NIST
source.title: 官方资料标题
source.url: 规范 HTTPS URL
source.version: 非空版本或发布日期
source.verified_at: UTC 核验日期
source.usage_note: 署名或许可证说明
content_sha256: 规范化知识卡内容哈希
```

知识卡 schema 拒绝未知字段、重复 ID、非白名单 URL、空建议、错误哈希和未批准发布方。知识卡不得包含可执行模板或原始攻击示例。

### 6.2 请求扩展

`AnalysisRequest` 增加可选字段：

```text
knowledge_mode: off | evidence | report = off
```

默认 `off` 保持现有行为和延迟。Web 高级控制可以显式选择 `evidence` 或 `report`。

### 6.3 响应扩展

`AnalysisResult` 增加可选知识字段：

```text
knowledge_status: off | ready | unavailable | degraded
knowledge_snapshot_version: string | null
knowledge_latency_ms: 非负数
knowledge_retrieval_latency_ms: 非负数
knowledge_report_latency_ms: 非负数
knowledge_evidence: 有序规范化证据列表
grounded_report: 结构化报告或 null
report_status: off | generated | fallback | unavailable
```

每条知识证据包含知识 ID、标题、简短摘要、处置建议、来源元数据、检索分数和命中标签，不包含净化查询。

研判报告包含简短解释、证据 ID、有序处置步骤和明确局限，不得包含新的决策字段。

## 7. 检索设计

检索使用两个确定性阶段：

1. 标签路由根据语义类别、CPD 状态、融合原因和可选攻击族筛选兼容知识卡。
2. SQLite FTS5 使用英文安全术语和预计算词法字段进行排序。中文内容在索引和查询前统一转换为确定性的重叠双字词，不能依赖 FTS 默认分词器切分中文长句。

组合分数使用在 development fixture 上冻结的权重，最终以稳定知识 ID 打破并列。最多返回 3 张知识卡，并暴露命中标签，确保排序可审计。

冻结评测后不得根据 test 标签修改检索权重。

## 8. 有依据的报告生成

`report` 模式通过受限生成适配器复用已经加载的 Qwen2.5。生成过程顺序执行、关闭采样，并限制最大输出长度。模型输入只包含：

- 规范化语义证据；
- 规范化 CPD 证据；
- 已确定的动作与工作模式；
- 已检索知识卡的摘要和允许使用的建议；
- 本次允许引用的知识 ID 列表；
- 固定结构化输出 schema。

报告 schema 不含决策字段。严格解析器拒绝未知字段、任何试图新增的决策字段、未知引用、空证据和结构化载荷之外的文字。原始模型输出解析后立即丢弃，不得返回或持久化。

模型不可用、超时、解析失败或引用失败时，确定性报告组合器直接根据规范化检测事实与知识证据生成降级报告，并明确显示 `fallback` 状态。

## 9. 失败处理

- 知识快照缺失或无效：返回已经完成的基础结果，并设置 `knowledge_status=unavailable`。
- 检索为空：从批准快照返回有界通用证据，或明确标记 `degraded`；不得编造来源。
- 报告超时或解析失败：保留检索证据并返回确定性降级报告。
- 审计失败：沿用基础任务行为，返回检测结果并设置 `audit_persisted=false`。
- 生成器 OOM：释放瞬时生成状态，只记录规范化错误类型，并直接降级；同一请求不重试。
- 任意知识层异常都不得改变基础任务的动作、检测分数、异常起点和语义证据。

## 10. Web 体验

分析输入区增加 `关闭`、`知识证据`、`研判报告` 三段式知识增强控制。关闭时，现有用户看不到行为变化。

现有 Token 轨道下方增加不嵌套卡片的知识证据区域，展示：

- 知识状态与快照版本；
- 命中的知识标题和证据标签；
- 官方发布方与来源链接；
- 忠于来源的风险说明；
- 有序处置建议；
- 模型生成或模板降级状态；
- 检索与报告延迟。

语义、CPD 和最终动作继续分别展示。知识区域不得在视觉或文案上暗示 RAG 改变了动作。

评测中心增加知识工程评测。安全事件可以显示快照版本和报告状态，但不得显示 Prompt、查询文本、知识卡正文或报告正文。

## 11. 评测与验收

仓库新增不含 Prompt 和攻击字符串的冻结检索 fixture。测试用例由安全合成查询词和固定检测元数据组成，覆盖现有语义类别、CPD 候选、Guard 不可用状态以及三个已评测攻击族标识符。

验收要求：

- 冻结 fixture 上 Retrieval Hit@3 不低于 90%；
- 引用有效率 100%；
- 基础动作一致率 100%；
- 知识卡 schema 与来源白名单有效率 100%；
- 禁止持久化字段数量为 0；
- SQLite、API 日志、报告与截图中的受保护 Prompt 命中数为 0；
- 索引缺失、空检索、生成失败、非法引用和超时均能返回基础结果；
- 在 AutoDL 记录检索、生成和端到端 P50/P95 延迟；
- 如实记录 OOM 数量；
- 不在定义的冻结工程 fixture 之外宣称语义准确率或 RAG 忠实度。

评测报告记录知识快照哈希、fixture 哈希、检索权重、运行时版本、模型版本，以及生成报告和降级报告数量。

## 12. 第二阶段：受控混合更新

在线更新器是独立管理流程，不能在请求分析期间运行。它只支持白名单 HTTPS 来源，并依次执行：

1. 下载到隔离暂存目录；
2. 校验来源身份、内容类型、大小与校验和；
3. 转换为候选知识卡；
4. 执行 schema、重复、URL、署名和禁止内容检查；
5. 展示与当前快照的可读差异；
6. 等待明确人工批准；
7. 创建不可变快照并原子切换；
8. 支持回滚到任意已批准快照。

网络失败时继续使用当前本地快照。禁止自动激活在线内容，比赛演示必须在断网状态下仍可完整运行。

## 13. 非目标

- RAG 不负责判定请求是否为 jailbreak。
- 知识层不执行外部处置动作或安全工具。
- 第一阶段不引入 LangChain、Chroma、FAISS 或 Embedding 模型。
- 项目不镜像 OWASP、MITRE 或 NIST 整站内容。
- 项目不展示隐藏模型推理，也不宣称支持思维链。
- BEAST、AutoDAN-HGA、PCAP 关联和自主 ReAct 处置不属于本阶段。

## 14. 交付物

- 版本化本地知识卡快照与 manifest；
- 严格知识卡加载器与 SQLite FTS5 索引；
- 安全查询构造器与确定性检索器；
- 带严格解析和降级机制的研判报告生成器；
- 可选 API 契约与规范化审计迁移；
- 分析页和评测页 Web 展示；
- 冻结检索 fixture 与仅含聚合数据的评测报告；
- AutoDL 部署、延迟、显存、失败和隐私验收；
- 来源署名、开发文档、测试报告、实验报告和三分钟演示更新。
