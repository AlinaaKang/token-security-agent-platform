# 主动式安全对话与 PCAP 取证角色设计

## 目标

将“安全对话”建设为平台的主要智能体入口。用户提交一次 Prompt 或 PCAP 后，智能体负责规划调查、调用已注册工具、解释公开证据并主动提出下一步。用户不需要记忆命令或自行组织完整工作流，但始终保留对实际动作的确认权。

“专业工作区”继续服务于需要手动选择参数、批量范围、画像方法和评测配置的专业分析人员，不与对话入口重复。

## 交互原则

- 对话优先：用户消息显示在右侧，Token Security 的回答、进度和工具结果显示在左侧，并按真实时间顺序追加。
- 主动推进：每次检测或动作完成后，智能体依据当前任务状态给出二至四个下一步，不让会话停在静态结论。
- 证据约束：检测结论来自现有 Prompt 检测器、PCAP 解析器和已注册工具；语言模型只负责理解、解释和组织表达。
- 用户控制：只读查询和解释可以直接执行；隔离、封禁、冻结账号等有影响的动作必须再次展示范围并取得授权。
- 真实标注：未接入的外部 EDR、防火墙、身份和 SIEM 能力不得伪装成真实执行。

## 对话范围

安全对话支持适度开放的自然交流，而不是只识别检测命令。

- 日常寒暄：你好、你在干嘛、谢谢、再见、你叫什么。
- 产品与能力咨询：你能做什么、如何上传 PCAP、报告在哪里、当前任务进行到哪里。
- 安全知识科普：Prompt 注入、越狱、SQL 注入、异常流量、攻击链和常见处置方法。
- 当前案件追问：为什么有风险、依据在哪里、异常从哪里开始、结论有什么限制。
- 安全学习建议：如何分析 PCAP、如何识别攻击类型、怎样修复危险 Prompt。

普通寒暄不得触发检测或申请授权。例如“你在干嘛”应回答正在等待安全问题或可以继续当前案件。对于写合同、旅游规划等明显无关且复杂的任务，智能体说明专业范围并引导回安全场景，不使用生硬的“超出范围”结束对话。

## 推荐追问与建议动作

最新一条智能体回复下方分成两个区域。

### 推荐追问

推荐追问帮助用户理解当前结果，不改变系统状态。点击后先追加一条右侧用户消息，再生成左侧智能体回答。

Prompt 示例：

- 具体发现了什么问题？
- 为什么判断为高风险？
- 异常从哪个 Token 开始？
- 这个结论有什么局限？

PCAP 示例：

- 哪些 Packet 最可疑？
- 可能是什么攻击类型？
- 攻击目的是什么？
- 为什么这些证据能够支持结论？

### 建议动作

建议动作是后端根据任务状态返回的类型化动作，不由前端临时拼接。按钮必须对应已注册且当前可用的工具；不可用的动作不展示。

Prompt 动作包括：

- 生成修复版本。
- 复检修复后的 Prompt。
- 生成调查报告。
- 在已有证据范围内继续调查。

PCAP 动作包括：

- 展开可疑 Packet 证据。
- 分析攻击链。
- 生成处置方案。
- 生成调查报告。
- 在重新授权后扩大调查范围。

点击动作即代表用户确认该目标。执行状态、工具回执、结果和失败原因都追加到同一会话；完成后重新计算下一轮推荐追问和建议动作。

## 主动工作流

### Prompt 调查

1. 用户提交 Prompt。
2. 智能体创建任务并展示调查计划。
3. 工具完成语义、Token 与知识证据分析。
4. 智能体解释风险位置、证据和限制。
5. 智能体主动提供修复、复检和报告动作。
6. 用户确认后，结果继续追加到当前会话。

典型链路为：

`检测 -> 解释异常位置 -> 建议修复 -> 生成修复版本 -> 重新检测 -> 生成报告`

### PCAP 调查

1. 用户在对话中上传 PCAP。
2. 上传、隔离解析和检测结果进入正式智能体任务状态，而不是停留在独立页面状态。
3. 智能体展示异常 Packet、攻击候选、证据强度和限制。
4. 智能体主动提供攻击链、处置方案、报告或扩大范围动作。
5. 用户确认后继续调用对应工具，并把观察结果追加到同一会话。

典型链路为：

`上传 -> 定位异常 Packet -> 判断攻击类型 -> 关联攻击链 -> 建议处置 -> 生成报告`

## 状态与接口

任务快照增加类型化 `next_actions`，每项至少包含稳定动作 ID、显示名称、动作类别、是否需要授权、当前是否可执行和不可执行原因。推荐追问与建议动作分开返回。

PCAP 检测任务必须进入与 Prompt 一致的会话持久化、历史恢复和消息追加机制。刷新或重新打开历史任务后，应恢复原消息顺序、时间、公开证据、动作状态和报告入口。

普通调查计划不再默认在后台悄悄生成报告。只有初始目标明确要求报告或完整闭环演示时才自动生成；其他场景在检测完成后由智能体主动提出“生成调查报告”。

动作接口必须验证：

- 动作属于当前任务返回的有效 `next_actions`。
- 当前任务状态允许执行。
- 所需工具真实存在且连接器状态符合要求。
- 有影响的动作携带未过期且范围匹配的授权。
- 同一动作不能因重复点击并发执行。

## 错误与降级

- 语言模型不可用时，返回确定性的证据摘要、固定追问和当前可执行动作，不丢失任务。
- 工具失败时显示失败工具、公开错误类型、未完成范围和可重试动作，不生成虚假的安全结论。
- PCAP 解析证据不足时明确说明未能定位异常，而不是把“未命中”表述为完全安全。
- 外部连接器未接入时隐藏真实处置动作，保留明确标注的内部仿真或只读建议。
- 动作执行期间禁用重复提交，但自由浏览历史消息和案件检查器不受影响。

## PCAP 侦探挑战三角色

PCAP 侦探挑战使用三个图标化取证角色，与 Token 侦探挑战的公仔、角色名称和动画体系完全分开。

1. **包解析员**：使用 `ScanSearch` 图标，负责读取协议、方向、时间和脱敏包内容，对应“标记异常位置”。
2. **流量关联员**：使用 `Network` 图标，负责比较正常基线、Packet 顺序和首次偏离，对应“判断攻击类型”。
3. **攻击研判员**：使用 `ShieldAlert` 图标，负责把 Packet 证据关联到攻击类型、目的和影响，对应“判断攻击目的”。

页面采用紧凑的三列取证流程条，使用统一蓝色线条和图标。桌面端横向排列，移动端纵向排列。不得使用人物图片、对话气泡、跳动公仔动画或 Token 挑战中的“语义侦探、曲线侦探、小队队长”名称。

每个角色区域说明它当前需要用户观察的证据，并与下方三个作答阶段保持同序。角色图标是导航和方法提示，不代替真实 Packet 证据。

## 隐私与审计

- 服务端不持久化原始 Prompt、PCAP 载荷、文件路径、IP、端口、账号或凭据。
- 浏览器本地可保存当前用户的原始 Prompt 用于恢复会话，并随任务删除操作清理。
- 传给语言模型的内容仅限当前任务的脱敏结构化事实、公开证据、限制和受限长度的最近对话。
- 对外展示的是可审计决策链、证据引用和工具回执，不展示隐藏模型思维或私有工具输出。
- 报告必须引用当前任务的公开证据，并标记真实、仿真、降级和未接入能力。

## 验收标准

- “你好”“你在干嘛”等普通交流得到自然回答，不触发调查。
- Prompt 与 PCAP 检测完成后都显示二至四个与状态匹配的推荐入口。
- 推荐追问只解释；建议动作会调用真实注册工具并在同一对话追加结果。
- 用户无需手写完整命令即可完成修复、复检、攻击链分析或报告生成。
- PCAP 上传结果能够刷新恢复并继续追问和执行动作。
- 有影响的动作未经授权不能执行，连接器未接入时不显示虚假真实动作。
- PCAP 侦探挑战显示三个图标化取证角色，并与 Token 公仔挑战明显不同。
- 桌面和移动布局中文字完整、按钮不遮挡输入框或案件检查器。

## 测试策略

- 后端单元测试覆盖任务状态到推荐追问及 `next_actions` 的映射、去重和授权要求。
- 协调器测试覆盖 Prompt 修复复检链、PCAP 攻击链与报告链、失败重试和重复点击。
- API 集成测试覆盖动作合法性、工具可用性、授权范围、消息顺序、刷新恢复和隐私字段排除。
- 前端测试覆盖追问与动作分区、点击后的消息追加、忙碌状态、普通寒暄和 PCAP 会话恢复。
- PCAP 挑战测试覆盖三个角色名称、图标语义、阶段顺序和 Token 公仔资产缺席。
- 生产构建后检查桌面与移动视口，确认对话、动作、右侧检查器和三角色流程无重叠。
