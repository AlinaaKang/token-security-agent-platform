# PCAP 多粒度局部异常定位设计规格

## 1. 设计状态

本规格扩展现有 PCAP SuperAgent，不替代现有 PCAP 安全沙箱与批处理设计。它解决当前版本只能输出协议统计、无法识别攻击或定位异常数据包的问题。

本规格尚未授权实现，也未授权读取真实 PCAP。实施前必须另行编写并批准实施计划。真实文件只能在用户通过页面完成一次性授权后进入 Docker 分析。

## 2. 核心目标

将现有 LLM Token 级局部归因思想扩展到异构安全证据单元：

- 普通网络流量定位到 Packet；
- 应用层交互定位到 Request 或 Response；
- 跨包行为定位到 Flow Event；
- 只有恢复出真实 LLM 请求时才定位到 LLM Token。

系统不要求所有 PCAP 使用 Entropy-CPD。智能体根据协议、序列长度、内容可见性和证据类型选择规则检测、行为异常检测或 CPD 边界定位，最终输出风险、攻击候选、局部位置、证据和处置建议。

对外表述为：

> 面向 AI 安全的 Packet-Request-Token 多粒度局部异常定位智能体。

## 3. 最高优先级非回归约束

以下现有能力必须保持行为不变：

- Prompt 安全调查页面及默认模式；
- 语义安全层与现有处置逻辑；
- Entropy-CPD、Token 热力图和异常起点；
- Prompt SuperAgent 的 objective、角色、工具、事件和报告；
- 安全事件、评测中心和攻防实验舱；
- Token 侦探挑战的关卡、计分、旗帜、Token 序号、公仔交互和动画；
- 现有 Prompt API、存储键、冻结样本和评测口径。

PCAP 新能力必须使用独立模型、组件、状态机、任务合同和测试。PCAP 失败不得改变 Prompt 健康状态、结果、延迟或动作。

## 4. 已知数据事实与未知项

对隔离目录的只读元数据检查确认：

- 共 2318 个文件，全部为 `.pcap`；
- 文件平铺在一个目录中，没有类别子目录；
- 没有 CSV、JSON、TXT、YAML 等独立标签文件；
- 文件大小跨度较大，大量文件较短，少量文件明显更大；
- 部分文件名疑似含传统 Web 攻击类别，另一部分为不可解释编号。

这些信息不能证明文件内容、攻击类型或标签质量。文件名不得作为检测输入。疑似文件名标签只能保存在私有评测层，作为弱文件级标签验证检测结果，不能进入 Agent、API、页面、报告或模型特征。

在真实 Docker 勘察完成前，以下事项保持未知：

- 捕获格式和链路层分布；
- 每个文件的数据包数量、持续时间和会话数量；
- HTTP、DNS、TLS、WebSocket 等协议占比；
- 明文应用层内容比例；
- Suricata 规则覆盖率；
- 单文件序列是否足以进行行为变化定位；
- 文件名弱标签与真实流量是否一致。

## 5. 第一阶段：20 文件分层安全勘察

现有“最小文件优先”适用于安全冒烟测试，不适合认识整个数据集。研究勘察采用独立且明确授权的分层采样：

1. 按文件大小四分位分为四组；
2. 每组确定性选择 5 个文件，共 20 个；
3. 选择规则只在私有工具层运行；
4. 每个文件使用独立 Docker 容器完整解析；
5. 容器禁止联网、非 root、只读根文件系统，并只读挂载当前文件；
6. 单文件结束后销毁容器和临时载荷；
7. 用户未在页面确认前，调用次数必须为零。

勘察只输出聚合结果：

- 有效与无效捕获数量；
- 包数量、持续时间和会话数量分布；
- 协议分布与明文比例；
- 规则告警类别及数量；
- 适合 Packet、Request、Flow Event 或 LLM Token 分析的样本数量；
- 适合 CPD 的长序列比例。

勘察不得输出原文件名、路径、IP、端口、MAC、Payload、HTTP 正文或稳定文件哈希。

## 6. Docker 内完整解析边界

为识别 SQL 注入、WebShell、命令执行等内容型攻击，Docker 内允许临时解析完整数据包和应用层载荷，但原始内容不得越过工具边界。

容器内允许：

- Tshark 解析逐包元数据、协议层和流关联；
- Suricata 检查应用层内容并生成规则告警；
- 私有适配器使用 IP、端口、时间和流标识完成内部关联；
- 计算局部序列特征、异常分数和包区间；
- 将规则告警映射到 Packet 或 Request。

容器外只允许：

- 随机匿名证据 ID；
- Packet 起止序号和相对时间；
- `packet`、`request`、`flow_event` 或 `llm_token` 粒度；
- 固定攻击候选类别；
- 固定检测器 ID 和规则类别；
- 有界异常分数与固定支持信号；
- 聚合计数和固定错误码。

禁止输出或持久化：

- 原文件名和任何宿主机路径；
- IP、端口、MAC 和五元组；
- 原始 Payload、URI、Header、Cookie、Body 和命令文本；
- 可反推出原文件的稳定哈希；
- Suricata、Tshark、Docker 或 PowerShell 原始错误文本。

## 7. 检测架构

```text
PCAP
  -> 一次性用户授权
  -> Docker 隔离分析
       -> Tshark 逐包与流事件提取
       -> Suricata 应用层规则检测
  -> 数据画像与检测路由
       -> 规则命中：Request/Packet 直接定位
       -> 行为异常：Packet/Flow Event 区间定位
       -> 长序列变化：可选 CPD 边界修正
       -> 真实 LLM 请求：现有语义与 Token 检测链
  -> 脱敏局部证据
  -> SuperAgent 证据融合
  -> 风险、攻击候选、位置与处置报告
```

### 7.1 Tshark 序列特征

逐包特征只保留检测需要的派生值：

- 相对时间；
- 包长度；
- 上下行方向的匿名类别；
- 协议类别；
- TCP Flags；
- 匿名 Flow 索引；
- 请求或响应事件类别；
- 窗口连接速率、目标密度、上下行比例和长度统计。

原始地址和内容只能用于容器内关联，生成派生特征后立即丢弃。

### 7.2 Suricata 规则证据

Suricata 负责已知攻击候选，包括但不限于：

- SQL 注入；
- WebShell 上传或通信；
- 命令执行；
- 漏洞探测和扫描；
- DNS 异常和隧道候选；
- 已有规则可以覆盖的恶意应用层交互。

公共结果只保留受控攻击类别和内部映射后的规则类别，不返回签名原文或应用内容。

### 7.3 行为异常与 CPD

行为检测用于规则未覆盖或跨包攻击：

- 扫描和连接突发；
- 周期性通信；
- 方向和长度分布异常；
- 异常数据外传候选；
- 协议或会话阶段突变。

CPD 只在序列长度和特征变化满足条件时用于定位阶段边界。短请求攻击、单次规则命中和序列不足样本不得强行运行 CPD。

### 7.4 LLM 证据升级

只有容器内真实识别并完整恢复 LLM 请求后，才允许调用现有 Prompt 检测链。恢复内容必须通过专用私有通道发送给现有模型，不能进入 PCAP 公共报告。

仅有 HTTP、WebSocket 或明文协议不能证明 LLM 流量；TLS 未解密时不能声称恢复 Prompt、检测 jailbreak 或定位异常 Token。

## 8. 检测路由规则

检测路由是确定性的受限策略，不由 LLM 任意选择宿主机工具：

| 条件 | 主检测器 | 定位粒度 | CPD |
|---|---|---|---|
| 应用规则明确命中 | Suricata/受控规则 | Request 或 Packet | 不要求 |
| 长时间扫描、突发或阶段行为 | 行为异常检测 | Packet 或 Flow Event 区间 | 可选 |
| 序列不足且无规则证据 | 证据不足 | 无 | 禁止 |
| 加密载荷且只有元数据 | 行为异常检测 | Packet 或 Flow Event | 可选 |
| 完整恢复 LLM 请求 | 现有语义与 Token 检测 | LLM Token | 使用现有逻辑 |

Agent 只能解释真实工具结果。规则与行为证据冲突时，报告必须分别列出证实项、候选项和未知项，不得由自然语言模型补造结论。

## 9. 公共局部证据合同

每个异常统一形成局部证据对象：

```json
{
  "evidence_id": "evidence_<random-id>",
  "granularity": "packet",
  "start_packet": 42,
  "end_packet": 58,
  "start_offset_ms": 12420,
  "end_offset_ms": 16080,
  "attack_candidate": "port_scan",
  "detector": "behavior_anomaly",
  "confidence": 0.87,
  "supporting_signals": [
    "connection_rate_increase",
    "destination_density_increase"
  ]
}
```

合同要求：

- `start_packet <= end_packet`；
- 序号必须落在已验证包数量内；
- 时间只使用捕获起点后的相对偏移；
- 攻击类别、检测器和支持信号使用封闭枚举；
- 置信度为有界数值且注明来源；
- 没有足够证据时不生成虚假区间；
- LLM Token 字段只能由现有模型真实运行结果产生。

## 10. PCAP 页面与公仔职责

Prompt 模式页面和行为保持原样。PCAP 模式独立展示：

### 10.1 规则侦探

复用现有 Guard 公仔图片，仅在 PCAP 专用组件中显示：

- 规则命中数量；
- 攻击候选类别；
- Request 或 Packet 区间；
- 明确的规则证据与限制。

### 10.2 序列侦探

复用现有 CPD 公仔图片，仅在 PCAP 专用组件中显示：

- 包序列异常曲线；
- 异常 Packet 或 Flow Event 区间；
- 实际使用的行为检测器；
- CPD 是否因满足条件而被调用。

短请求攻击由规则完成定位时，页面显示“规则证据已完成局部定位，无需调用 CPD”，不得显示成系统失效。

### 10.3 小队队长

继续使用已证实、候选、未知和建议动作四类结构，汇总：

- 风险等级；
- 攻击候选；
- 定位粒度与区间；
- 主检测器和辅助证据；
- 证据冲突；
- 处置建议。

### 10.4 Packet 时间轴

时间轴高亮异常区间。悬停只显示 Packet 序号、相对时间、协议、匿名 Flow ID、异常分数和规则类别。布局必须在桌面和移动端无横向溢出。

## 11. 错误与降级

- Docker 不可用：固定环境错误，不读取文件；
- 文件损坏或格式不支持：固定文件错误，继续下一项；
- Tshark 或 Suricata 超时：清理容器后返回固定工具错误；
- 序列太短：跳过行为模型和 CPD，保留规则结果；
- 无规则且无行为证据：返回证据不足，不报警；
- TLS 未解密：只做元数据行为检测；
- 两个检测器冲突：降低置信度并要求人工复核；
- Agent 超时、JSON 无效或引用未知证据：退回确定性模板；
- 用户取消：当前容器清理完成后停止，不提前发布终态；
- PCAP 模块失败：Prompt 模式继续正常运行。

## 12. 实验与评测

### 12.1 数据审计

首轮 20 文件分层勘察报告必须先回答：

- 样本是否足以支持 Packet 序列定位；
- 应用层明文和规则命中比例；
- 短捕获与长捕获比例；
- 哪些攻击更适合规则、行为或混合检测；
- 文件名弱标签是否有明显噪声。

审计结论决定后续方法权重，不允许预先声称 CPD 是主检测器。

### 12.2 检测指标

- 文件级攻击召回率、精确率、F1 和正常文件误报率；
- 各攻击类别召回率与混淆矩阵；
- 规则单独、行为单独、混合智能体的消融结果；
- 未知或证据不足比例。

### 12.3 定位指标

若存在精确区间标签：

- 起点绝对误差；
- Packet 区间 IoU；
- Request 定位命中率；
- Flow Event 区间覆盖率。

若只有文件级弱标签：

- 不得虚构定位真值；
- 使用规则命中位置、人工抽样复核和跨检测器一致率作为辅助证据；
- 定位效果只能表述为案例验证，不能表述为有监督定位准确率。

### 12.4 系统指标

- 单文件和每批延迟；
- 容器超时与失败率；
- 取消和断点续跑正确率；
- 残留容器数量；
- 公共边界隐私字段命中数；
- Prompt 与挑战页非回归测试结果。

## 13. 验收标准

只有同时满足以下条件，才能声明新 PCAP 检测能力完成：

1. 用户授权的 20 文件分层勘察完成并形成脱敏聚合报告；
2. 至少一种真实攻击类型被检测并定位到 Packet 或 Request；
3. 正常或证据不足样本不会因曲线变化被强制报警；
4. 每个告警包含风险、攻击候选、位置、检测器、证据和建议动作；
5. CPD 只在真实调用时显示结果，未调用时显示原因；
6. 原始 Payload、身份字段和路径未越过 Docker 工具边界；
7. Prompt 模式及挑战页全部既有测试原样通过；
8. 规则、行为和融合方法完成消融对比；
9. Docker 沙箱、隐私验证、取消、续跑和 Git 排除检查通过；
10. 未将普通 PCAP 结果错误描述为 LLM Token、jailbreak 或 Entropy-CPD 结果。

## 14. 实施顺序

1. 新增只读、分层、一次性授权的数据勘察任务；
2. 扩展 Docker 镜像，加入 Suricata 与受控输出适配器；
3. 实现逐包与 Request 局部证据合同；
4. 根据勘察结果选择最小可行行为检测方法；
5. 实现确定性检测路由与 Agent 融合；
6. 增加 PCAP 专用公仔证据和 Packet 时间轴；
7. 完成合成测试、隐私测试和 Prompt 非回归测试；
8. 经用户页面授权后运行真实样本验收；
9. 根据真实结果再决定是否扩大到全部 2318 个文件。

在第 1 阶段真实勘察完成前，不锁定行为模型、窗口大小、CPD 算法或阈值。
