# Token 侦探挑战设计规格

## 1. 目标与定位

在不改变基础检测页、专业实验舱、冻结指标或安全动作的前提下，为比赛现场增加一个可互动的游戏化演示模式“Token 侦探挑战”。玩家根据逐步揭示的脱敏证据判断处置动作、证据关系和 CPD 异常起点，系统使用真实 AutoDL 检测结果评分并解释。

该模式的目标是让评委在 2–3 分钟内理解三项核心能力：

1. Guard 判断语义风险；
2. Entropy-CPD 检测并定位 Token 分布变化；
3. Agent 使用固定融合、反事实和知识证据形成处置结论。

游戏分数只衡量玩家答案与本次系统结果的一致程度，不表示模型准确率、攻击成功率、检测召回率或 CPD 定位准确率。

## 2. 设计原则

- 基础页面稳定优先：`/analyze`、`/events`、`/evaluation` 的路由、契约和页面行为不得改变。
- 专业模式保持完整：现有 `/lab` 调查工作台不重构，游戏使用隔离的新页面和状态。
- 真实结果负责揭晓：公仔、动画和计分不得产生或改写安全结论。
- 受保护输入不出边界：冻结攻击只发送 `sample_id`，浏览器不接收攻击原文、suffix、Token 文本或 Token ID。
- 游戏状态不持久化：分数、连击和进度只保存在 React 内存中，刷新或退出即清除。
- 无反作弊承诺：完整检测结果已返回浏览器，界面仅按阶段隐藏字段；该模式用于现场演示和教学，不用于有奖竞赛或正式考试。
- 可访问性优先：所有操作均可用键盘完成，减少动态效果偏好会关闭位移动画。

## 3. 路由与信息架构

新增 `/challenge` 路由，并在实验舱区域提供模式切换：

```text
AI 安全攻防实验舱
├── 专业调查       /lab
└── Token 侦探挑战 /challenge
```

挑战页面保持四个稳定区域：

```text
┌────────────────────────────────────────────┐
│ 模式｜关卡进度｜分数｜连击｜退出挑战      │
├────────────────────────────────────────────┤
│ Guard 侦探｜CPD 侦探｜Agent 队长          │
├────────────────────────────────────────────┤
│ Token 风险轨道与真实检测曲线               │
├────────────────────────────────────────────┤
│ 证据关系｜放行/复核/拦截｜提交判断         │
└────────────────────────────────────────────┘
```

提交后保持相同布局，切换到揭晓状态，显示玩家答案、系统答案、得分、真实起点、关键证据、技术解释和下一关命令。

## 4. 公仔与视觉资产

采用已确认的“侦探学院小队”三角色。整体造型使用大头短肢、圆润轮廓、眼神高光、轻微腮红和小侦探帽，在软萌感与比赛专业感之间保持平衡：

- Guard 侦探：绿色主色，帽徽为盾牌，负责语义线索；
- CPD 侦探：蓝色主色，帽徽为变化点折线，负责曲线扫描和变化点插旗；
- Agent 队长：黄色强调色，帽徽为圆形队长章，负责融合、报告和处置揭晓。

公仔使用项目内透明背景位图资产，不依赖远程 URL。每个角色使用一张稳定尺寸的中性姿态 PNG 或 WebP；等待、调查、发现证据和完成状态通过 CSS 位移、缩放、亮度、状态徽标和 Lucide 图标组合表达，不为每个状态维护独立图片。三只角色共享同一视觉家族，但面部表情、帽檐角度和徽章细节保持轻微差异，避免机械复制感。

动画不得暗示不存在的并行调用或因果关系。角色亮起顺序来自 `LabStage` 的真实顺序，CPD 插旗位置来自 `suspicious_span.token_start`。在 `prefers-reduced-motion: reduce` 下，位移动画替换为无过渡的状态切换。

现有实验舱 API 在整次调查完成后一次性返回结果，因此公仔动画明确标记为“调查过程回放”，不是实时流式执行。回放时长只服务于讲解，不作为模型阶段耗时；真实耗时继续显示服务端返回的 `latency_ms`。

## 5. 挑战模式

### 5.1 三关速战

默认比赛演示模式，目标时长 2–3 分钟：

1. 普通无害：双路正常，验证放行；
2. 无害格式突变：观察 CPD 敏感性与语义证据如何避免误判；
3. 优化型攻击：优先选择当前目录中的 AutoDAN；不可用时依次回退到 GCG、AdvPrompter。

### 5.2 五关完整挑战

目标时长 5–7 分钟：

1. 普通无害；
2. 无害格式突变；
3. GCG；
4. AutoDAN；
5. AdvPrompter。

关卡在会话开始时从 `GET /api/v1/lab/scenarios` 解析。受保护关卡按 `attack_family` 匹配，不在前端硬编码 sample ID。若完整挑战缺少任一攻击族，则入口显示缺少的族并禁止开始，不用其他族冒充。

当前不加入直接危险、BEAST 或 AutoDAN-HGA 关卡，因为没有完成对应的受保护来源验收。

## 6. 单关状态机与数据流

单关状态固定为：

```text
ready
→ investigating
→ guessing
→ submitted
→ revealed
→ next | complete
```

数据流：

```text
选择挑战模式
→ 解析脱敏场景目录
→ 使用场景 ID 调用 POST /api/v1/lab/runs
→ AutoDL 执行 Guard、Token 观测、Entropy-CPD、固定融合、知识报告
→ 前端立即把完整结果保存在当前组件内，但只揭示允许作答的线索
→ 玩家选择证据关系、处置动作和可选异常起点
→ 纯前端评分器与 LabRunResult 对比
→ 显示揭晓、反事实敏感性和技术解释
```

挑战不得调用新的模型端点。现有实验舱运行仍会进入 32 条、15 分钟的脱敏内存窗口和实验舱运行指标，但玩家分数、连击和逐题答案不得进入后端指标。

## 7. 玩家输入与证据揭示

调查完成后进入 `guessing`：

- 显示 Guard 的语义等级；
- 显示 Entropy、NLL 和 CPD 曲线；
- 隐藏基础动作、融合原因、反事实结果、知识报告和工具计划；
- 玩家选择证据关系；
- 玩家选择 `allow`、`review` 或 `block`；
- 存在有效 `suspicious_span` 时，玩家在曲线上选择预测 Token 索引；否则起点控件不可用并标记“不适用”。

证据关系选项固定为：双路正常、仅语义风险、仅分布异常、双路风险。只有语义状态为 `safe` 或 `unsafe` 且检测器状态可判定时，该题计分。`controversial`、`unavailable` 或检测器不可用时，证据关系项不适用。

## 8. 确定性评分

基础分值：

- 处置动作：50 分；
- 证据关系：20 分；
- 异常起点：30 分。

异常起点规则：

- 与 `suspicious_span.token_start` 距离不超过 3 Token：30 分；
- 距离 4–8 Token：15 分；
- 距离超过 8 Token：0 分；
- 没有有效起点：该项不适用。

证据关系由服务返回字段直接映射：

```text
safe   + no_token_anomaly       → 双路正常
unsafe + no_token_anomaly       → 仅语义风险
safe   + token_anomaly_candidate → 仅分布异常
unsafe + token_anomaly_candidate → 双路风险
```

最终分数按适用项归一化：

```text
round_score = round(earned_points / applicable_points * 100)
```

处置动作始终适用，因此 `applicable_points` 不低于 50。连击只控制角色庆祝和界面反馈，不增加基础分，避免隐藏加分规则。总分是各关百分制分数的算术平均值。

## 9. 公仔状态映射

- `ready`：三名角色静态等待；
- `investigating`：根据真实 `LabStage` 顺序依次亮起；
- Guard 线索可用：Guard 侦探举起语义等级牌；
- CPD 告警：CPD 侦探在曲线对应 Token 位置插旗；
- 证据冲突：Guard 与 CPD 同时显示分歧徽标；
- `submitted`：Agent 队长进入融合状态；
- `revealed`：显示系统动作、反事实敏感性和得分；
- 工具失败演示：显示处置工具失败徽标，同时明确基础安全动作未降级。

所有角色台词使用固定模板和结构化字段，不把模型原始输出当作台词，也不显示模型思维过程。

## 10. 组件边界

新增前端模块：

- `ChallengePage`：页面装配、模式选择和错误状态；
- `ChallengeSession`：内存关卡状态机；
- `ChallengeStage`：三公仔、曲线、答题与揭晓布局；
- `MascotTeam`：角色状态映射；
- `ChallengeAnswerPanel`：玩家输入；
- `ChallengeReveal`：结果、解释和下一关；
- `challengeScoring.ts`：无副作用的确定性评分函数；
- `challengeDefinitions.ts`：三关和五关定义及场景目录解析。

复用模块：

- `api.labScenarios`；
- `api.createLabRun`；
- `LabSignalChart` 的几何计算与信号类型；
- 现有 `LabRunResult`、`Decision`、`Mode` 类型。

`ChallengePage` 不导入或改写 `LabPage` 内部状态。可复用的曲线几何若目前封装在组件内部，只做针对性提取，不重构专业实验舱其他区域。

## 11. 隐私与安全边界

挑战模式沿用实验舱七个禁用字段：

- `prompt`
- `suffix`
- `token_text`
- `token_id`
- `query_text`
- `raw_output`
- `guard_raw_output`

要求：

- 冻结攻击请求只包含 `scenario_kind=frozen`、`sample_id` 和 `mode`；
- 不使用 `localStorage`、`sessionStorage`、IndexedDB 或 Cookie 保存游戏状态；
- 不新增截图、日志或遥测上传；
- 玩家答案、得分、连击和角色状态不进入正式事件库；
- 页面错误信息使用固定错误码映射，不回显响应体或受保护输入；
- 公仔资产不得包含攻击文本、凭据、真实网络地址或数据集内容。

## 12. 故障与降级

- Lab 未启用或 GPU 不可用：挑战入口显示“挑战暂不可用”，专业调查和基础页面不受影响；
- 场景目录缺失：显示缺少的攻击族，完整挑战禁止开始；
- 单关 API 失败：保留当前关卡和玩家未提交状态，允许重试，不扣分；
- CPD 无有效起点：定位项不适用，按其余适用项归一化；
- 语义或检测证据不可用：证据关系项不适用，基础动作仍可评分；
- 知识或反事实不可用：揭晓页明确标记降级，不影响基础动作评分；
- 玩家中途退出：立即清除内存会话，返回专业实验舱；
- 工具失败模拟：不得把 `block` 降为 `review` 或 `allow`。

## 13. 响应式与可访问性

- 桌面端四个区域保持稳定高度，动态文本和角色状态不得引起整体跳动；
- 手机端按进度、角色、曲线、答题顺序纵向排列；
- 曲线只在自身容器内横向滚动，不产生全局横向溢出；
- 按钮触控目标至少 44px；
- 选项、曲线索引、提交和下一关均可用键盘操作；
- 颜色不是唯一状态信号，必须同时提供文字或图标；
- 公仔图片提供描述角色职责的 `alt` 文本，装饰性状态标记使用空 `alt`；
- `prefers-reduced-motion` 下关闭移动、弹跳和连击动画。

## 14. 测试与验收

### 14.1 单元测试

- 三关和五关定义解析正确；
- 缺少攻击族时完整挑战不可开始；
- 动作、证据关系、起点边界和归一化分值使用字面量用例验证；
- 不适用项不会被算作错误；
- 连击不改变基础分；
- 评分函数不修改 `LabRunResult`。

### 14.2 前端行为测试

- 从模式选择到完成挑战的状态机完整；
- 作答前不显示基础动作、融合原因和反事实答案；
- 提交后玩家答案与系统答案均可见；
- API 失败可重试且不扣分；
- 退出和刷新不恢复会话；
- 渲染 DOM 不含七类禁用字段或受保护测试字符串；
- 键盘可以完成整局。

### 14.3 回归与隐私测试

- 现有后端与前端全量测试继续通过；
- `/analyze`、`/events`、`/evaluation` 和 `/lab` 的现有契约不变；
- 隐私验证器命中数保持 0；
- Git 不新增原始 Prompt、SQLite、缓存、截图或 `.secrets` 内容。

### 14.4 视觉验收

使用 Playwright 在 1440×900 与 390×844 检查：

- 角色、公仔台词、曲线、答案与导航不重叠；
- 三关和五关的动态内容不改变主要控件位置；
- 页面无全局横向溢出；
- 画布或图表路径非空；
- 减少动态效果生效；
- 视觉 QA 只使用安全合成内容或受保护 sample ID。

### 14.5 AutoDL 验收

- 三关速战完整运行一次；
- 五关挑战完整运行一次；
- GCG、AutoDAN、AdvPrompter 各至少完成一关；
- 三族响应禁用字段命中数为 0；
- 游戏开始前后基础 `/health` 状态一致；
- 记录实际关卡状态、计分、P50/P95 和失败数，不记录攻击原文。

## 15. 非目标

- 不开发多人联网、排行榜、账号、奖励兑换或长期存档；
- 不提供攻击 Prompt 编辑器或攻击生成器；
- 不声称游戏分数是检测性能；
- 不接入真实防火墙、SOC、工单、PCAP 或第三方游戏平台；
- 不新增 BEAST、AutoDAN-HGA 或未经来源验证的直接危险关卡；
- 不为游戏新增后端数据库或常驻 GPU 服务。

## 16. 完成标准

只有同时满足以下条件，Token 侦探挑战才可标记完成：

1. 默认三关和完整五关均可从开始运行到结算；
2. 三只公仔状态由真实结构化结果驱动；
3. 评分边界和不适用规则有自动测试；
4. 受保护关卡只发送 sample ID，所有公开响应禁用字段命中为 0；
5. 基础页面与专业实验舱的契约和视觉回归未改变；
6. 桌面、手机、键盘和减少动态效果验收通过；
7. AutoDL 三攻击族真实挑战通过，限制在材料中如实记录。
