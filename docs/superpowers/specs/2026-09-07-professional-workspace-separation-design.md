# Prompt 与 PCAP 专业工作区分离设计

## 目标

让 Prompt 和 PCAP 功能按输入类型清晰归位，消除独立“安全案件”分组和实验舱内部跨类型切换。保留现有路由兼容、检测算法、授权流程、事件数据、PCAP Docker 隔离边界与 Token 侦探挑战规则。

## 导航结构

`Prompt 专业工作区`包含：

- `Prompt 安全分析`：同一工作区内提供“检测分析”和“安全事件”两个视图。
- `Prompt 攻防实验`：只显示 Prompt 攻防内容。
- `Prompt 评测中心`。
- `Token 侦探挑战`。

`PCAP 专业工作区`包含：

- `PCAP 上传检测`。
- `PCAP 攻防实验`：只显示 PCAP 攻防内容。
- `PCAP 侦探挑战`：独立页面复用真实 PCAP 异常检测、Packet 定位和检测小队能力。

左侧删除独立的`安全案件`分组。旧 `/events` 路由继续可用并显示 Prompt 安全分析工作区的安全事件视图。

## Prompt 分析与事件

`/analyze`显示工作区级切换控件：

- `检测分析`保留现有 Prompt 输入、双检测器证据、融合处置、Token 轨道和知识证据。
- `安全事件`保留现有脱敏事件统计、表格和解释。

两个视图共享“Prompt 安全分析”导航选中状态。切换视图不修改或删除事件记录，不显示原始 Prompt。

## 实验舱隔离

- `/lab?surface=prompt`从 URL 得到固定 Prompt 模式，只渲染 Prompt 攻防。
- `/lab?surface=pcap`从 URL 得到固定 PCAP 模式，只渲染 PCAP 攻防。
- 页面内部删除 Prompt/PCAP 切换控件。
- 旧 `/lab`默认进入 Prompt 模式，保持旧链接兼容。

## PCAP 侦探挑战

`/pcap-challenge`使用独立标题、说明和挑战边界，内部复用现有 `PcapDetectionWorkspace`。参与者必须显式授权真实检测，完成后通过规则侦探、序列侦探、小队队长和 Packet 时间轴复盘结果。该页面不伪造分数，不复制 Token 挑战，也不改变 PCAP 检测阈值。

## 欢迎区布局

快捷入口按实际数量自动等分：Prompt 的四项保持四列，PCAP 的三项填满三列并整体居中；窄屏保持单列。

## 验收

- 左侧只保留安全对话、Prompt 专业工作区、PCAP 专业工作区和智能体资源四组。
- Prompt 安全分析内部可切换检测与事件。
- 两个实验 URL 不再显示输入类型切换。
- PCAP 侦探挑战有独立路由且复用真实检测能力。
- PCAP 欢迎区三个入口等宽居中。
- 全量前端测试、生产构建、差异检查和桌面/移动端截图通过。
