# 统一可解释 AI 安全智能体工作台设计

## 1. 产品定位

平台定位为“面向大模型应用安全事件的可解释自主调查与处置智能体”。它解决一个明确安全痛点：当大模型应用收到可疑输入或其网络流量出现异常时，安全人员难以同时完成语义判断、Token 级定位、PCAP 证据分析、知识研判、攻击目的解释和处置留痕。

平台不是通用办公助手，也不宣称覆盖所有漏洞扫描、恶意软件逆向或企业 SOC 场景。Prompt、PCAP、知识、仿真端点、仿真身份和仿真日志均服务于同一个“大模型应用安全事件调查”场景。

当前赛事方官方平台不可用，团队已获得不使用官方平台的许可。产品继续使用自研平台和现有 AutoDL、本机 Docker 能力，提交材料只陈述这一合规事实，不保存私人沟通、账号或凭证。

## 2. 比赛任务映射

### 2.1 基础任务：单一场景化安全智能体

基础任务主线保持为“大模型应用异常输入检测、Token 级定位与处置”。真实能力包括：

- Qwen3Guard 语义安全判断；
- Qwen2.5-7B 完整 logits 与 Entropy-CPD Token 异常候选和起点定位；
- 固定融合策略与安全动作；
- 脱敏事件、证据摘要和处置建议；
- 围绕同一安全事件的自然语言任务入口和结果追问。

PCAP 是该事件的网络侧证据扩展，不改变基础任务算法、冻结指标或 Token 侦探挑战。

### 2.2 进阶任务：领域知识与工具扩展

进阶任务由两类能力构成：

- 离线 RAG：复用 OWASP、MITRE、NIST 知识快照、FTS5 Top-3 检索、知识引用验证和确定性报告回退；
- 代码工具：复用 Docker/tshark PCAP 解析、批量分诊、数据勘察、异常检测、证据包、安全案件和内部网关状态工具。

新增攻击科普与 PCAP 解释工具，将检测证据转换为受知识库约束的说明，包括攻击类别、常见目的、证据含义、不能证明的内容、建议复核步骤和可用 Wireshark 显示过滤器。说明不得把异常候选表述为攻击成功。

### 2.3 挑战任务：有边界的 SuperAgent 自主闭环

挑战任务展示用户目标理解、可见计划、跨源案件、工具调度、观察反馈、动态重规划和结果收口。系统展示完整的结构化 CoT：调查问题、候选假设、支持证据、反证、工具观察、置信度变化、计划修订和最终结论全部可见。系统只保护系统提示词、模型内部临时草稿、原始推理 Token 和其他敏感实现信息，不以“隐藏思维链”为理由省略可审计调查过程。每个判断必须能回溯到公开证据、知识引用、工具回执或明确标注的仿真证据。

真实数据源：Prompt 检测、Token 证据、PCAP 检测、离线知识、平台内部工具回执。

仿真数据源：端点进程、身份账号和安全日志。所有仿真证据在数据模型、API、页面和报告中始终显示“仿真”，不得进入基础或进阶任务的真实检测指标。

在缺少真实防火墙、EDR、身份和 SIEM API 时，系统只提供连接器接口和明确标注的仿真适配器。一次明确授权之后，智能体可以在授权范围内无人干预地完成调查；扩大读取范围、上传新文件或执行真实外部处置仍需再次授权。

## 3. 目标与非目标

### 3.1 目标

1. 用户可以用自然语言创建 Prompt、PCAP 或联合安全调查任务。
2. 智能体将目标转换为类型化、可验证、可恢复的执行计划。
3. 计划根据真实工具观察结果追加、跳过或替换步骤。
4. 所有工具调用受允许列表、参数模式、次数、时间、读取范围和授权约束。
5. 用户可以追问当前案件、要求调整范围、重试失败项或生成报告。
6. 页面明确区分异常、检测失败、当前范围未命中、真实证据和仿真证据。
7. 现有 Prompt、PCAP、实验舱、评测中心和 Token 侦探挑战保持可用。
8. 调查同时维护多个候选假设，并显示支持、反对、未知和置信度变化。
9. 跨源证据按时间线关联，处置动作完成后必须再次观察并验证效果。

### 3.2 非目标

- 不实现无约束的自由工具调用或任意代码执行。
- 不让对话模型直接读取原始 PCAP、Token 文本、隐藏 Prompt 或私人路径。
- 不伪造真实防火墙、EDR、身份或 SIEM 联动。
- 不把教学科普内容当成检测证据。
- 不用动画、未经验证的自由文本或模型内部临时草稿伪造调查过程。
- 不修改现有冻结检测算法、阈值、融合表和 Token 侦探挑战规则。

## 4. 总体架构

系统采用“模型提议、策略验证、受控执行、证据校验”的混合智能体架构。

```text
用户消息 / 文件选择 / 数据源选择
                |
                v
       意图与任务参数理解器
                |
                v
       受约束计划生成器 --------- 确定性回退计划
                |
                v
       计划与权限策略验证器
                |
                v
       可恢复任务状态机
                |
                v
       类型化安全工具注册表
                |
                v
       结构化观察与证据仓库
                |
                v
       假设评估器 / 重规划器 / 结果验证器
                |
                v
       对话回答 / 案件报告 / 处置回执
```

大模型只能输出符合 JSON Schema 的意图、计划提议、候选假设和解释草稿。策略层负责验证目标类型、工具 ID、参数来源、授权、最大步骤数、依赖关系、证据引用和置信度范围。任何验证失败都使用确定性回退计划或请求用户补充信息，不执行模型提出的未知动作。

## 5. 对话与智能体人格

智能体采用专业、自然、克制的安全分析师人格。默认身份回答为：“我是 Token Security 安全智能体，主要协助完成大模型应用安全检测、PCAP 调查、异常定位、知识研判和处置报告生成。”

支持的对话意图分为：

1. 身份与帮助：名称、能力、数据边界、使用方式和当前工具状态。
2. 安全知识：Prompt 注入、越狱、XSS、模板注入、SSRF、SQL 注入、扫描行为、TLS/DNS/HTTP 等概念。
3. 任务创建：调查 Prompt、PCAP 数据集、单个 PCAP 或已有安全案件。
4. 案件追问：异常文件、证据位置、攻击目的、置信边界、失败原因和建议动作。
5. 任务控制：继续、暂停、取消、重试、跳过、调整批次和扩大范围。
6. 交付物：生成或更新 Markdown 报告、证据清单和处置记录。
7. 简单日常交流：简短自然回应后引导回安全任务；复杂非安全请求说明专业范围，不调用安全工具。

对话记忆只保存脱敏任务摘要、用户允许的偏好、任务 ID、计划和公开证据引用。用户在对话中提交的待检测 Prompt 只瞬时传给现有分析接口；持久化消息使用固定占位符和字符数，不保存原文。不得保存原始 Prompt、payload、Token 文本/ID、文件路径、网络身份或模型隐藏输出。

## 6. 类型化任务与生命周期

任务类型包括：

- `prompt_investigation`：Prompt 语义、Token、知识和反事实调查；
- `pcap_dataset_investigation`：目录清点、分批检测、异常定位和聚合报告；
- `pcap_capture_investigation`：单个授权上传文件的隔离检测；
- `cross_domain_case`：将已有 Prompt/PCAP 结果与仿真端点、身份、日志关联；
- `knowledge_explanation`：仅进行知识问答，不触发检测或文件读取；
- `report_generation`：基于已有公开证据生成或更新报告。

任务状态为 `draft`、`awaiting_authorization`、`planned`、`running`、`paused`、`completed`、`degraded`、`failed` 或 `cancelled`。状态转换必须由公开事件驱动并持久化，页面刷新后可以恢复。

每个任务默认最多 12 个计划步骤、3 个并发工具、2 次基于观察的重规划和 5 个同时活跃的候选假设。每次工具调用使用工具注册表声明的超时，任务达到预算后进入 `paused` 或 `degraded`，不得无限等待。具体预算由能力接口公开并集中配置，不允许模型修改。PCAP 文件仍以最多 20 个为一个检测批次，但任务可在授权范围内连续创建多个批次，因此“20”是执行批次上限，不是整个数据集上限。

### 7.1 多假设调查与反证

每个复杂调查维护一组类型化候选假设，例如正常业务波动、自动化扫描、Prompt 注入、认证绕过、内部地址探测或数据提取。每个假设包含公开描述、支持证据、反对证据、未知条件、当前置信度和状态 `active|supported|rejected|inconclusive`。

置信度只由代码定义的证据权重和冲突规则更新，模型不能直接覆盖数值。系统必须展示假设被提升、降低或排除的原因。证据冲突时不得强行收敛为高风险结论；应追加验证步骤或进入人工复核。

### 7.2 跨源时间线与处置后验证

Prompt、PCAP、知识、工具回执和仿真遥测使用公开相对时间与关联 ID 组成攻击时间线，不公开私人网络或身份字段。处置工具完成后，协调器必须调用只读验证工具观察策略状态或演示案件状态，记录“已验证、未生效、无法验证”之一；没有验证证据时不得宣称闭环成功。

## 7. 计划与动态重规划

初始计划由任务类型、已授权数据源和可用工具生成。每个步骤包含：步骤 ID、目的、工具、依赖、所需授权、输入引用、预期输出、状态和公开说明。

重规划只由类型化观察触发：

- PCAP 解析失败：尝试兼容解析器；仍失败则标记并继续其他文件。
- 只发现加密流量：跳过 payload 规则，使用 TLS、DNS 和流量行为证据。
- HTTP 异常候选：追加请求定位、攻击目的归因和响应关联。
- Prompt 语义与 Token 证据冲突：追加反事实检查与人工复核建议。
- 知识证据不足：使用确定性解释，明确“知识不足”，不编造引用。
- 工具暂时失败：在预算内重试；超过预算后降级收口。
- 用户调整范围：验证新授权后生成计划修订版本。

模型可以提出修订，但状态机只接受允许的条件和工具。每次计划变化展示“触发观察、原计划、新计划和理由摘要”。

## 9. 科普与 PCAP 解释能力

### 9.1 攻击科普

用户可以询问攻击名称、原理、常见目的、证据含义、可能误报和处置建议。回答优先使用当前案件证据和离线知识引用；没有案件时提供一般说明，并明确它不是当前环境的检测结论。

### 9.2 PCAP 助手

PCAP 助手支持：

- 解释 PCAP/PCAPNG、包、流、会话和请求之间的区别；
- 说明 HTTP、TLS、DNS、TCP 等协议证据；
- 解释“packet 4-4”等区间表达；
- 根据公开证据生成 Wireshark 显示过滤器；
- 对异常候选说明触发规则和目的候选；
- 对解析失败说明格式、截断、非目标协议、超时或工具错误；
- 区分“异常候选”“检测失败”“未命中”和“攻击成功”。

科普回答不得暴露页面未授权展示的 IP、端口、payload、原始请求、文件名、路径或哈希。只有在用户显式选择允许展示的本地实验数据时，专业检查器才可展示对应公开字段。

### 9.3 框架映射、相似案件与处置推演

当前案件可以映射到 OWASP LLM Top 10、MITRE ATLAS 和适用的 ATT&CK 技术，并显示映射证据与不确定性。相似案件检索只使用脱敏标签、攻击类别、协议和证据模式，返回相似点与差异点，不因历史结论相同而自动复制处置。

处置推演比较“阻断、隔离、限速、清洗后重检、人工复核”等选项的预期收益、业务影响、可逆性和所需授权。推演结果属于 `simulated` 或 `derived`，不能伪装成真实执行。

## 10. 统一 Web 工作台

整个网站使用统一应用外壳，但保留现有路由兼容性。

### 10.1 左侧栏

- 新建安全任务；
- 安全案件与任务历史；
- 专业工作区：安全分析、攻防实验舱、评测中心、Token 侦探挑战；
- 智能体资源：检测技能、知识库、数据连接器和报告；
- AutoDL、本地 Docker 和连接器状态。

已确认视觉方向为通透浅蓝侧栏、深蓝灰文字、半透明蓝色选中项和蓝色品牌图标。分组标题需要显著高于普通项目文字。

### 10.2 中央任务流

中央区域展示用户消息、智能体公开回答、执行计划、授权节点、工具调用、进度、计划调整、异常结论和交付物。底部输入框支持自然语言、Prompt、PCAP 和数据源引用。

智能体头像使用蓝色。可审计调查链使用统一蓝色，避免把阶段装饰色误解为状态；红、绿、黄分别只用于异常、成功和执行失败/待复核。

### 10.3 右侧检查器

右侧根据当前选择显示：

- 文件列表和自动滚动进度；
- Prompt/Token 或 PCAP 证据；
- 真实/仿真来源标识；
- 工具状态和执行回执；
- 报告预览与引用；
- 当前步骤的输入、输出和限制。
- 候选假设、支持/反对证据和置信度变化；
- 跨源攻击时间线与处置后验证状态。

桌面使用三栏。窄屏隐藏右侧检查器并通过标签页或底部抽屉打开；手机使用单栏、左侧抽屉和不少于 44px 的关键控件。

## 11. 案件、证据与可解释性

统一案件包含任务摘要、计划版本、公开事件、证据引用、工具回执、结论、限制和报告。每条证据包含来源类型、真实性 `real|simulated|derived`、生成工具、时间、可公开摘要和引用 ID。`real` 表示真实工具对授权输入产生的直接结果，`simulated` 表示版本化内置演示数据，`derived` 表示基于已引用证据生成的解释或报告；派生证据不能替代直接检测证据。

最终结论必须同时提供：

1. 发现了什么；
2. 哪些证据支持；
3. 推断的攻击目的；
4. 不能证明什么；
5. 哪些文件检测失败或未覆盖；
6. 建议的下一步；
7. 已执行和未执行的处置动作。

“完整思维链”在产品中实现为完整结构化 CoT：任务理解、候选假设、支持与反对证据、工具选择、观察、置信度变化、计划修订、处置验证和结论均可审计。系统提示词、模型内部临时草稿和原始推理 Token 不属于安全调查证据，不公开；用户可验证的调查过程不得省略。

## 12. API 与持久化

新增统一命名空间：

- `POST /api/v1/agent/tasks`：创建草稿任务或知识问答；
- `POST /api/v1/agent/tasks/{task_id}/messages`：继续对话或提交控制意图；
- `POST /api/v1/agent/tasks/{task_id}/authorizations`：授权特定目的与范围；
- `GET /api/v1/agent/tasks/{task_id}`：恢复任务快照；
- `GET /api/v1/agent/tasks/{task_id}/events`：SSE 推送公开任务事件；
- `POST /api/v1/agent/tasks/{task_id}/cancel`：显式取消；
- `GET /api/v1/agent/tasks`：分页任务历史；
- `GET /api/v1/agent/capabilities`：工具、连接器和边界状态。

SSE 断开后使用 `Last-Event-ID` 恢复，无法使用 SSE 时退回有界轮询。SQLite 保存脱敏任务、消息意图、计划、事件、证据引用和报告元数据。PCAP 内容继续只由 Docker 读取；原始 Prompt 和私人文件身份不进入智能体数据库。

## 13. 错误与恢复

- 模型不可用：使用确定性意图和计划回退，页面明确显示能力降级。
- AutoDL 不可用：知识问答和本地 PCAP 能力仍可用；Prompt 检测步骤保持等待或失败，不伪造结果。
- Docker/tshark 不可用：PCAP 任务进入可重试失败，不影响已有结果和其他任务。
- SSE 中断：自动重连并从最后事件继续；多次失败后退回轮询。
- 页面刷新或切换工作区：任务继续运行，重新订阅相同任务，不隐式取消。
- 服务重启导致底层临时任务丢失：统一任务保留审计状态并提示重新授权重试。
- 工具返回未知字段、错误目标或错误任务 ID：拒绝合并到案件。
- 报告引用无效：使用确定性模板并标记知识报告降级。

只有用户明确点击取消或发送明确取消意图时才调用取消端点。

## 14. 安全与隐私边界

- PCAP 内容读取保持无网络、只读根文件系统、非 root、能力全丢弃、禁止提权和资源受限 Docker。
- 文件选择、数据源授权和外部处置使用目的绑定、范围绑定、一次性或短时授权。
- 用户对话视为不可信输入，不能覆盖系统策略、工具允许列表或证据真实性标识。
- 模型解释只能消费公开结构化证据，不直接消费私人 payload 或隐藏 Token。
- 所有真实与仿真来源在 API 层标记，前端不能自行推断或改写标记。
- 报告和截图不得包含受保护 Prompt、suffix、Token 文本/ID、原始模型输出、私人路径、密钥或未授权网络身份。

## 15. 分阶段交付

### 阶段 A：统一外壳与可恢复任务

建立三栏工作台、任务历史、对话消息、计划/事件模型、SSE/轮询恢复和现有路由兼容。知识问答与身份问答首先可用。

### 阶段 B：真实 Prompt 与 PCAP 工具化

把现有 Prompt、PCAP 勘察、批量检测、单文件检测和结果解释注册为类型化工具。实现自然语言任务创建、授权、进度和失败恢复。

### 阶段 C：动态重规划、科普与报告

根据结构化观察调整计划，增加多假设反证、证据冲突、攻击/协议科普、框架映射、Wireshark 过滤器、相似案件、处置推演、引用报告和交付物面板。

### 阶段 D：跨域案件与仿真连接器

加入明确标注的端点、身份和日志仿真连接器，完成跨源案件、关联链和一次授权后的自主闭环演示。

### 阶段 E：安全剧本、连接器与反馈

提供版本化安全剧本模板、连接器能力中心和分析员反馈记录。剧本只组合已注册工具、条件、授权点和失败回退；不能创建任意代码节点。反馈只形成审计记录与离线改进建议，不在线修改冻结阈值。

每个阶段都必须保持现有页面和检测算法测试通过，不能等待全部阶段完成后再集中验证。

## 16. 测试与验收

### 16.1 功能验收

1. 身份、能力和安全知识问答不创建检测任务。
2. 自然语言 Prompt 任务调用真实现有检测并返回一致结果。
3. PCAP 数据集任务在一次范围授权后连续执行多个 20 文件批次。
4. 切换任务、路由或刷新页面不取消后台任务。
5. 工具观察可以真实触发计划追加、替换或降级。
6. 真实与仿真证据在 API、页面和报告中始终一致。
7. 报告中的每个风险结论都有证据引用和限制说明。
8. 用户可追问异常文件、攻击目的、失败原因和未覆盖范围。
9. 只有显式授权或取消触发对应副作用。
10. Token 侦探挑战逻辑和冻结检测指标不变。
11. 复杂案件至少展示两个候选假设及一条反证，且置信度变化可追溯。
12. 跨源时间线区分真实、仿真和派生事件。
13. 处置完成后有独立验证观察；无法验证时最终状态不能显示“已闭环”。
14. 框架映射、相似案件和处置推演均包含证据范围与不确定性。

### 16.2 安全验收

- 对话注入不能创建未知工具、扩大路径或跳过授权；
- 重放、过期、目的错误和范围错误的授权全部拒绝；
- 私人字段扫描覆盖所有任务、事件、SSE、报告和错误响应；
- 仿真数据不能进入真实指标或被展示成真实联动；
- PCAP 继续通过 Docker 隔离门禁。

### 16.3 视觉和可访问性验收

在 1440x900、390x844 和键盘导航下验证三栏/单栏布局、任务恢复、长文件名、长中文消息、进度变化、错误状态和报告预览。页面不得水平溢出、遮挡主要操作或依赖颜色作为唯一状态信号；减少动态效果设置下关闭非必要动画。

## 17. 比赛演示主线

演示从一句目标开始：“调查这批大模型应用流量，找出异常文件，分析攻击目的并生成处置报告。”

智能体依次展示目标理解、数据源授权、公开计划、Docker PCAP 检测、Prompt/Token 证据、离线 RAG、仿真端点/身份/日志关联、观察触发的计划调整、证据验证、内部处置回执和 Markdown 报告。演示全程显示真实/仿真来源、失败与未覆盖范围，不宣称攻击成功或真实外部设备已经被控制。
