# 挑战任务：有界 SuperAgent 自主闭环

## 1. 任务定位

挑战任务在基础检测和进阶实验舱之上增加一个可审计的自主处置层。它不重新判断 Prompt，也不改写基础动作，而是读取实验舱已经生成的脱敏证据，完成固定权限内的规划、观察、一次重规划、工具调用和收口。

Web 入口为 `/super-agent`，页面明确标注“平台内部仿真闭环”。当前实现用于证明从发现到处置的自主协作流程，不代表已经接入外部防火墙、EDR、SIEM 或工单系统。

## 2. 自主闭环

一次任务只接受冻结样本 ID 和工作模式，执行以下公开状态：

1. `PLAN`：协调员建立固定调查计划。
2. `ACT`：复用实验舱执行基础检测与反事实检查。
3. `OBSERVE`：语义、Token、知识角色分别读取脱敏证据。
4. `REPLAN`：协调员根据不可变基础动作选择内部工具，最多一次。
5. `ACT`：响应执行员按确定顺序调用零到三个内部工具。
6. `OBSERVE`：核验回执；失败时保留基础动作并降级收口。
7. `COMPLETE`：输出结构化最终状态。

页面展示的是确定性审计事件，不是模型隐藏思维链。事件只包含角色、阶段、固定摘要、证据代码、工具 ID 和执行状态。

## 3. 角色与权限

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| `coordinator` | 规划、汇总、重规划、收口 | 不能读取原始输入，不能降低基础动作 |
| `semantic_analyst` | 读取归一化语义等级与类别 | 不读取 Guard 原始输出 |
| `token_analyst` | 读取 CPD 状态与脱敏异常起点 | 不读取 Token 文本或 Token ID |
| `knowledge_analyst` | 核验知识状态和真实知识 ID | 不读取检索词或模型原始输出 |
| `response_operator` | 调用平台内部处置工具并核验回执 | 不能发起网络、子进程或外部设备操作 |

## 4. 固定策略

| 基础动作 | 最终工具计划 | 正常收口状态 |
| --- | --- | --- |
| `allow` | 无 | `closed_safe` |
| `review` | 安全案件、证据归档包 | `review_required` |
| `sanitize_recheck` | 安全案件、证据归档包 | `review_required` |
| `block` | 内部网关状态、安全案件、证据归档包 | `contained` |

任一已选工具失败时，最终状态为 `degraded`。失败不会导致动作降级，也不会触发无限重试。

## 5. 有界性与幂等性

- 每个任务只创建一个实验舱 run。
- 最多一次重规划、三次工具调用、十二条公开轨迹事件。
- 每个工具最多执行一次，按任务 ID 和工具 ID 生成确定性 UUIDv5 幂等键。
- 任务结果只在带 TTL 和容量限制的内存存储中保留，不序列化到磁盘。
- 已确认工具仍复用实验舱的 SQLite 幂等执行器；所有动作必须等于或强于基础动作。

## 6. 隐私边界

任务请求和响应不包含原始 Prompt、攻击 suffix、Token 文本或 ID、检索词、Guard 原始输出、模型原始输出、隐藏推理、密钥或私人路径。知识引用只展示后端真实返回的 `knowledge_id`。

`scripts/verify_lab_privacy.ps1` 会扫描健康、实验舱和 SuperAgent 的响应表面，包括能力、任务创建、任务恢复和固定 422。扫描器只输出表面、违规类别和聚合计数，不打印响应正文或匹配值。

## 7. 使用方式

1. 启动 GPU 后端和 Web 前端。
2. 打开 `http://127.0.0.1:5175/super-agent`。
3. 选择一个已就绪的冻结场景和工作模式。
4. 点击“启动自主任务”。
5. 查看五个角色的回报、命令轨道、内部工具回执和最终状态。

安全样本应以 `closed_safe` 收口且工具调用为零；拦截样本应按固定顺序形成三条内部回执。受保护样本只显示标签、攻击族和脱敏证据，不显示攻击原文。
